# 정보화전략계획 (ISP)
## PULSE·16 → 음원 상품화 파이프라인

작성 기준일 2026-08-02 · As-Is 는 저장소 실측값

---

## 1. 개요

### 1.1 배경

PULSE·16 은 16스텝 시퀀서로 출발했지만, 실제로 축적된 자산은 시퀀서가
아니라 **장르 지식의 구조화된 데이터베이스**입니다.

- 프리셋 357종이 계열 12 · 하위분기 64로 분류돼 있음
- 각 프리셋이 박자·음색·화성·타악기·볼륨까지 장르 규칙으로 매핑됨
- 그 근거가 마크다운 51개 10,679줄로 문서화돼 있음
- 음색 엔진 70종이 **측정으로 검증**돼 있음 (배음 구조를 실물 기준값과 대조)

여기에 최근 16마디 선율 21종 · 4마디 프레이즈 22 · 송폼 5종이 더해지면서
"소리를 내는 도구" 에서 "**곡의 뼈대를 생성하는 자산**" 으로 성격이 바뀌었습니다.

한편 생성형 음악 AI(Suno 등)는 **음향 렌더링과 보컬**은 잘 하지만
**구조적 일관성**(장르 관용구, 16마디 형식, 편성의 정합성)이 약합니다.
이 둘은 상호보완적입니다.

### 1.2 목적

**PULSE·16 이 만든 구조화된 음악 시드를 생성형 AI 에 투입해
완성 트랙을 만들고, 이를 유통까지 잇는 파이프라인을 구축한다.**

### 1.3 범위

| 구분 | 포함 | 제외 |
|---|---|---|
| 기능 | 선율·송폼 라이브러리, 시드 익스포트(MIDI/오디오/프롬프트), 트랙 관리, AI 연동, 유통 메타데이터 | 실시간 협업, 보컬 합성 자체 개발, DAW 대체 |
| 대상 | 개인 창작자(1인) → 소규모 팀 | 대규모 SaaS 다중 테넌트(3단계 이후 검토) |
| 기간 | 12개월 3단계 | — |

### 1.4 추진 체계

현재 1인 개발 체계입니다. 이 문서는 그 전제로 작성했습니다.
외주가 필요한 항목(법률 자문, 유통 계약)은 별도 표기했습니다.

## 2. 환경 분석

### 2.1 외부 환경

| 영역 | 관찰 | 시사점 |
|---|---|---|
| 기술 | 생성형 음악 AI 가 음향·보컬 품질에서 실용 수준 도달 | 렌더링을 직접 만들 이유가 없음 — **구조 생성에 집중** |
| 기술 | 텍스트 프롬프트만으로는 장르 관용구 재현이 불안정 | 구조화된 시드의 가치가 여기서 생김 |
| 시장 | 배경음악·숏폼·게임용 저비용 음원 수요 | 대량 생산에 유리한 파이프라인이 유효 |
| 법제 | AI 생성물의 저작물성·학습데이터 적법성 논쟁 진행 중 | **최대 리스크. §7 참조** |
| 경쟁 | 프롬프트 기반 생성 서비스 다수 | 차별점은 "장르 정확도" 와 "재현 가능성" |

> 시장 규모·성장률 수치는 의도적으로 넣지 않았습니다.
> 검증 없는 숫자는 계획을 왜곡합니다. 필요하면 별도 조사 후 보강하십시오.

### 2.2 내부 환경 (보유 역량)

**강점**

- **검증 문화가 이미 있음.** 계측 하네스 9개 + MCP 서버로 소리를 귀가 아니라
  수치로 판정합니다. 실제로 기타 기음이 27dB 죽어 있던 결함, 피아노가
  순수 사인이던 결함을 측정으로 잡았습니다. 이건 흔치 않은 자산입니다.
- **자료가 코드보다 많음.** 마크다운 10,679줄이 데이터 357종의 근거입니다.
  "왜 이 값인가" 가 남아 있어 확장 시 판단 비용이 낮습니다.
- **모듈 분리 완료.** 7,090줄 단일 HTML 을 38파일로 갈랐고, 분리 전후
  로직이 동일함을 검증했습니다.

**약점**

- **서버가 없음.** 저장이 브라우저 localStorage 단일 키입니다.
  기기를 옮기면 작업이 사라지고, 트랙을 여러 개 관리할 수 없습니다.
- **전역 스코프.** 클래식 스크립트 구조라 로드 순서가 곧 의존 순서입니다.
  파일이 더 늘면 관리가 어려워집니다.
- **자동 테스트가 없음.** 계측 하네스는 음향 품질 검증이지 회귀 테스트가
  아닙니다. 리팩토링 안전망이 사람의 주의력에 의존합니다.
- **익스포트 경로가 없음.** 현재 결과물을 밖으로 낼 방법이 WAV 녹음(MCP 도구)
  뿐입니다. MIDI·프로젝트 파일·프롬프트 텍스트 어느 것도 안 나갑니다.
  **이것이 파이프라인의 가장 큰 단절점입니다.**

## 3. 현황 분석 (As-Is)

### 3.1 기능 관점

```
[사용자] ──▶ 프리셋 선택 ──▶ 롤 편집 ──▶ 재생 ──▶ (끝)
                                              └── 밖으로 나가는 길이 없음
```

| 기능 영역 | 현황 | 평가 |
|---|---|---|
| 장르 프리셋 | 357종, 계열·하위분기 분류 | ● 충분 |
| 음색 | 70 엔진, 측정 검증 | ● 충분 |
| 리듬 | 7 드럼 트랙 + 필인 18종 | ● 충분 |
| 화성 | 아키타입 39종 (1마디) | ◐ 1마디 반복 한계 |
| 선율 | 16마디 21종 + 프레이즈 22 | ◐ 신규, 검증 미흡 |
| 송폼 | 5종 (AABA 등, 16마디 단위) | ◐ 곡 전체 구조는 없음 |
| 편곡 | 트랙별 음색·볼륨 장르 매핑 | ● 충분 |
| **저장** | localStorage 1개 슬롯 | ✕ **결손** |
| **익스포트** | 없음 | ✕ **결손** |
| **AI 연동** | 없음 | ✕ **결손** |
| **유통** | 없음 | ✕ **결손** |

### 3.2 데이터 관점

자산은 많지만 **형식이 코드에 묶여 있습니다.**

| 데이터 | 현재 형태 | 문제 |
|---|---|---|
| 프리셋 357 | JS 리터럴 (장르별 12파일) | 코드 로드 없이 못 읽음 |
| 선율·필인·송폼 | JS 리터럴 | 상동 |
| 장르 지식 | 마크다운 51개 | 사람만 읽을 수 있음 (기계 판독 불가) |
| 사용자 작업물 | localStorage JSON 1건 | 백업·이전·버전관리 불가 |

### 3.3 기술 관점

| 항목 | 현황 | 위험 |
|---|---|---|
| 실행 | 브라우저 단독 (file:// 가능) | 낮음 — 배포가 쉬움 |
| 의존 | Tone.js CDN, 샘플 외부 호스팅 | **중** — 외부 중단 시 기능 상실 |
| 구조 | 클래식 스크립트 전역 스코프 | 중 — 확장 시 충돌 위험 |
| 테스트 | 없음 (계측 하네스만) | **중** — 회귀 탐지 불가 |
| 보안 | 인증·권한 개념 없음 | 낮음(현재) / **높음**(다중 사용자 시) |

### 3.4 문제점 종합

| # | 문제 | 근거 | 영향 |
|---|---|---|---|
| P1 | 결과물이 밖으로 안 나감 | 익스포트 기능 부재 | **파이프라인 성립 불가** |
| P2 | 트랙을 하나밖에 못 다룸 | localStorage 단일 키 | 상품화 규모 한계 |
| P3 | 곡 전체 구조가 없음 | 16마디까지만 있음 | MVP 트랙 제작 불가 |
| P4 | 장르 지식이 기계 판독 불가 | 마크다운 산문 | AI 프롬프트 자동 생성 불가 |
| P5 | 회귀 탐지 불가 | 자동 테스트 부재 | 확장 속도 저하 |

| P7 | 법적 지위 불확실 | 저작권·AI 약관 | **사업 전체 중단 가능** |

## 4. 목표 모델 (To-Be)

### 4.1 비전

> **장르를 아는 시드를 만들고, AI 가 소리를 입히고, 사람이 고른다.**

### 4.2 To-Be 서비스 흐름

```

 │ 장르 선택 → 송폼 조립 → 선율·화성·편성 자동 배치  │
 │            → 사람이 손보기                        │
 └───────────────────────┬──────────────────────────┘
                         ▼  시드 익스포트
        ┌────────────────┼────────────────┐
        ▼                ▼                ▼
    MIDI(.mid)      스템 오디오       구조 프롬프트
   구조·음정 정보   레퍼런스 음향     장르·편성·형식 텍스트
        └────────────────┼────────────────┘
                         ▼
              ┌──── 생성형 AI (Suno 등) ────┐
              │  음향 렌더링 · 보컬 · 마스터  │
              └──────────────┬──────────────┘

              ┌──── 선별·품질 게이트 ────┐
              │ 자동: 라우드니스·트루피크  │  ← 기존 MCP 계측 자산 재사용
              │ 사람: 청감 · 장르 적합성   │

                             ▼

| 방향 | 내용 | 근거 |

```

**T01 을 1순위에 둔 이유** — 나머지 12개 과제의 전제입니다. AI 생성물을
상업적으로 쓸 수 없다고 판명되면 파이프라인 자체가 성립하지 않습니다.
개발보다 먼저 확인해야 합니다.

**T04(MIDI) 를 T05(오디오)보다 앞에 둔 이유** — MIDI 는 구조 정보를
그대로 담고 파일이 작으며, 생성형 AI·DAW 양쪽이 다 받습니다.
오디오는 용량이 크고 이미 렌더된 소리라 활용도가 낮습니다.

## 6. 이행 계획

### 6.1 단계 구성

| 단계 | 기간 | 목표 | 과제 |
|---|---|---|---|
| **1단계 — 검증** | 1~3개월 | 파이프라인이 성립하는지 확인. **MVP 트랙 1곡** | T01 T02 T03 T04 T13 |
| **2단계 — 연결** | 4~8개월 | 시드→AI→선별을 자동으로 연결 | T06 T07 T09 T10 T12 |
| **3단계 — 규모화** | 9~12개월 | 여러 트랙을 관리·유통 | T05 T08 T11 |

### 6.2 단계별 상세

**1단계 (1~3개월) — 검증**

목표는 기능이 아니라 **답**입니다. "이 방식으로 팔 만한 곡이 나오는가?"

- T01 법·약관 검토 → **게이트**. 부정 결론이면 2단계 진입 중단
- T02 곡 단위 송폼 (인트로 4 + 절 16 + 후렴 16 + 브릿지 8 + 아웃트로 4)
- T03 선율 21 → 60종, 계열별 최소 5종
- T04 MIDI 익스포트 (드럼·베이스·건반·기타 4트랙)
- T13 Tone.js·샘플 로컬화
- **산출: MVP 트랙 1곡 완성 (시드 → AI → 선별 → 마스터)**

> 1단계는 자동화하지 않습니다. AI 투입과 선별을 **손으로** 해서
> 파이프라인의 값어치를 먼저 확인합니다. 자동화는 값어치가 확인된 뒤입니다.

**2단계 (4~8개월) — 연결**

- T06 마크다운 51개의 장르 지식을 JSON 스키마로 (템포·편성·관용구·금기)
- T07 그 JSON 으로 구조 프롬프트 자동 생성
- T09 AI 연동 어댑터 (**T01 결과에 따라 대상 서비스 확정**)
- T10 품질 게이트 — 기존 `audio_measure` 를 배치로
- T12 회귀 테스트 — 프리셋 로드·엔진 발음·저장 복원

**3단계 (9~12개월) — 규모화**

- T08 서버 저장소 + 다중 트랙 + 버전
- T05 스템 오디오 익스포트
- T11 유통 메타데이터

| ID | 위험 | 영향 | 가능성 | 대응 |

| R5 | 생성물 품질 편차 | 중 | 높음 | 품질 게이트(T10) + 후보 N개 생성 후 선별 |
| R6 | 1인 운영의 지속성 | 중 | 중 | 자동화 우선순위를 반복 작업에 둠 |

### 7.1 선결 확인 항목 (T01 상세)

**개발 착수 전 반드시 문서화된 답을 확보할 것.**

1. 대상 AI 서비스의 요금제별 **상업적 이용 권리** 범위
2. 공식 API 유무. 없으면 **서드파티 래퍼 사용의 약관 위반 여부**
3. 국내법상 **AI 생성물의 저작물성** — 사람의 창작적 기여를 어디까지
   인정하는지 (본 파이프라인은 선율·화성·편성을 사람이 정하는 구조)
4. 음원 유통사의 AI 생성물 **등록 정책**
5. 저작권 신탁단체 등록 가부

3~5번은 **법률 자문·유통사 문의가 필요**하며 자체 판단으로 갈음하면 안 됩니다.

## 8. 기대 효과

| 구분 | 효과 | 측정 지표 |
|---|---|---|
| 정성 | 장르 정확도가 프롬프트 방식보다 높음 | 청감 평가 (블라인드 비교) |
| 정성 | 같은 시드로 재현 가능 | 동일 시드 재투입 시 구조 일치 여부 |

> 나온 뒤에야 의미 있는 추정이 가능합니다. 그 전 숫자는 희망사항입니다.
