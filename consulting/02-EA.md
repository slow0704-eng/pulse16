## 1. 업무 아키텍처 (BA)

### 1.1 업무 기능 분해 (To-Be)

```
음원 상품화
├── 1. 창작 준비
│   ├── 1.1 장르 선택            (기존)
│   ├── 1.2 송폼 조립            (신규 — 곡 단위)
│   └── 1.3 선율·화성 배치        (부분 신규 — 16마디까지 존재)
├── 2. 시드 생성
│   ├── 2.1 편성 확정            (기존 — TONE_KIT)
│   ├── 2.2 구조 프롬프트 작성    (신규)
│   └── 2.3 익스포트             (신규 — MIDI/오디오/JSON)
├── 3. AI 렌더링
│   ├── 3.1 시드 투입            (신규)
│   ├── 3.2 후보 수집            (신규)
│   └── 3.3 재시도 판단          (신규)
├── 4. 선별
│   ├── 4.1 자동 계측            (기존 자산 재사용 — MCP)
│   └── 4.2 청감 심사            (신규 — 사람)
└── 5. 유통
    ├── 5.1 메타데이터 부여       (신규)
    └── 5.2 배포·이력            (신규)
```

**기존/신규 비율이 곧 개발량입니다.** 창작 준비는 대부분 있고,
2~5 단계가 통째로 없습니다. ISP 가 "익스포트를 최우선" 으로 둔 이유입니다.

### 1.2 As-Is vs To-Be 업무 흐름

| 단계 | As-Is | To-Be |
|---|---|---|
| 장르 결정 | 프리셋 칩 클릭 | 동일 |
| 구조 | 1마디 반복 | 곡 단위 송폼 |
| 편성 | 자동 매핑 | 동일 |
| 출력 | **없음** | MIDI + 프롬프트 + 참조 오디오 |
| 완성 | **없음** | AI 렌더 → 선별 |
| 유통 | **없음** | 메타데이터 → 배포 |

## 2. 응용 아키텍처 (AA)

### 2.1 현행 (As-Is)

```
브라우저 (단일 페이지, 클래식 스크립트 38파일)
├── core   config · engines · scale · dom · state · util
├── data   preset-index · pattern-codec · presets(12) · fills · melody
├── audio  graph · string · sampler · params · voice-{drum,bass,keys,gtr}
├── seq    sequencer
├── ui     meters · build · edit · events
└── main
                    │
                    ▼
        localStorage (단일 키)
```

**특징과 제약**

- 전역 렉시컬 스코프 공유. `<script>` 순서가 곧 의존 순서
- 실행하는 파일은 `main.js` 하나. 나머지는 선언만
- 서버·인증·다중 사용자 개념 없음

```
┌─────────────────────── 브라우저 ───────────────────────┐
│                                                        │
│  ┌── 표현 계층 (UI) ──────────────────────────────┐   │
│  │  기존 ui/*  +  송폼 편집기 · 익스포트 · 심사큐   │   │

│  │  + 송폼 엔진 · 시드 빌더                        │   │

        ┌───────────────┴───────────────┐

┌── 백엔드 (최소) ──┐          ┌── 외부 서비스 ──┐
```

### 2.3 계층 원칙

| 계층 | 책임 | 금지 |
|---|---|---|
| 표현 | 화면·입력 | 도메인 규칙을 갖지 않음 |
| 코어 | 음악 도메인 (장르·선율·편성·합성) | **외부 서비스를 직접 부르지 않음** |
| 어댑터 | 외부 규격 변환 | 음악적 판단을 하지 않음 |
| 백엔드 | 보관·자격증명 | 음악 처리를 하지 않음 |

**어댑터 계층이 핵심 방어선입니다.** ISP R2(AI 서비스 약관·API 변경)의
영향을 이 계층 안으로 가둡니다. 코어는 "시드 객체" 만 만들고,
그것을 어떤 서비스의 어떤 형식으로 보낼지는 어댑터가 압니다.

### 2.4 신규 응용 컴포넌트

| 컴포넌트 | 계층 | 책임 | ISP 과제 |
|---|---|---|---|
| 송폼 엔진 | 코어 | 섹션(인트로·절·후렴·브릿지·아웃트로)을 마디로 전개 | T02 |
| 시드 빌더 | 코어 | 곡 전체를 직렬화 가능한 시드 객체로 | T04·T07 |
| MIDI 인코더 | 어댑터 | 시드 → SMF(.mid) | T04 |
| 오디오 렌더러 | 어댑터 | 시드 → 스템 WAV (OfflineAudioContext) | T05 |
| 프롬프트 생성기 | 어댑터 | 시드 + 장르 JSON → 텍스트 | T07 |
| AI 클라이언트 | 어댑터 | 투입·수집·재시도 | T09 |
| 저장소 클라이언트 | 어댑터 | 프로젝트 CRUD | T08 |
| 품질 게이트 러너 | 백엔드 | 후보 일괄 계측 | T10 |

## 3. 데이터 아키텍처 (DA)

### 3.1 데이터 분류

현행의 가장 큰 문제는 **성격이 다른 데이터가 한곳에 섞여 있다**는 것입니다.

| 분류 | 성격 | 현행 위치 | 목표 위치 |
|---|---|---|---|
| **라이브러리** | 읽기 전용, 버전 관리 대상 | JS 리터럴 | JSON + 코드 분리 |
| **프로젝트** | 사용자 작업물, 자주 변경 | localStorage 1건 | 서버 저장소 |
| **산출물** | 생성 결과, 대용량 | 없음 | 오브젝트 스토리지 |
| **지식** | 사람이 읽는 근거 | 마크다운 51개 | 마크다운 + 기계판독 JSON |

### 3.2 주요 엔티티 (To-Be)

```
Genre ──< SubGenre ──< Preset
                          │
Preset ──── kit(음색) ────┤
       ──── bcfg(베이스) ─┤
       ──── patterns ─────┘

SongForm ──< Section (kind, bars, melodyRef, formRef)

Melody ──< Phrase (4마디) ──< Bar (16스텝)

Project ──< Track ──< Seed ──< Candidate ──< QualityReport
                                    │
                                    └──< Release (메타데이터)
```

### 3.3 핵심 엔티티 정의

| 엔티티 | 주요 속성 | 비고 |
|---|---|---|
| `Preset` | name, cat, sub, bpm, swing, kit, bcfg, patterns[7], bass, keys, gtr | 현행 357건 |
| `SongForm` | name, sections[] | 신규. 곡 전체 |
| `Section` | kind(intro/verse/chorus/bridge/outro), bars, presetRef, melodyRef, energy | 신규 |
| `Seed` | songForm, genre, key, scale, bpm, instrumentation, bars[] | 신규. **익스포트 단위** |
| `Candidate` | seedId, provider, uri, createdAt | 신규. AI 생성 결과 |
| `QualityReport` | candidateId, lufs, truePeak, crest, dc, verdict | **기존 계측 출력 형식 그대로** |
| `Release` | candidateId, title, isrc, credits, genreTags, status | 신규 |

### 3.4 장르 지식의 기계 판독화 (T06)

마크다운 10,679줄에서 **기계가 쓸 수 있는 사실**만 뽑아 JSON 으로 만듭니다.

```
knowledge/genre/{subgenre}.json
{
  "name": "Bossa Nova",
  "cat": "H", "sub": "브라질",
  "bpm": [120, 140],
  "instrumentation": { "required": ["nylon","upright","shaker"],
                       "optional": ["piano"], "avoid": ["hi","supersaw"] },
  "rhythm":  { "feel": "straight", "swing": [0,20] },
  "melody":  { "density": [3,6], "contour": "sparse-long" },
  "prompt":  { "keywords": ["bossa nova","nylon guitar","brushed drums"],
               "avoid": ["distorted guitar","808"] }
}
```

산문은 마크다운에 그대로 두고, **JSON 은 사실만** 담습니다.
두 벌을 두는 대신 마크다운을 원본으로 삼고 JSON 을 파생물로 관리합니다.

### 3.5 데이터 이관

| 대상 | 현행 | 목표 | 방법 |
|---|---|---|---|
| 프리셋 357 | JS 리터럴 12파일 | JSON | 빌드 시 추출. 코드는 JSON 로드로 변경 |
| 선율·필인·송폼 | JS 리터럴 | JSON | 상동 |
| 사용자 작업물 | localStorage | 서버 | 최초 로그인 시 업로드 마이그레이션 |
| 장르 지식 | 마크다운 | 마크다운 + JSON | 수작업 추출 (자동화 어려움 — 산문이라) |

> 프리셋의 JSON 화는 **파일 로드가 비동기**가 되므로 초기화 순서를
> 손봐야 합니다(현재 `_build.js` 가 동기 실행 전제).
> `ARCHITECTURE.md` 의 로드 순서 규칙과 충돌하는 지점입니다.

## 4. 기술 아키텍처 (TA)

### 4.1 현행

| 계층 | 기술 | 비고 |
|---|---|---|
| 실행 | 브라우저 (Chromium 계열 검증) | file:// 직접 열기 가능 |
| 오디오 | Web Audio API + Tone.js 14.7.77 | CDN 의존 |
| 저장 | localStorage | 단일 키 |
| 검증 | Node + Playwright + ffmpeg (MCP 서버) | 로컬 전용 |

### 4.2 목표

| 계층 | 기술 방향 | 선정 이유 |
|---|---|---|
| 프런트 | 현행 유지 (클래식 스크립트) | 동작 검증됨. 재작성 이득 없음 |
| 라이브러리 | Tone.js **로컬 번들** | ISP R7. CDN 단절 위험 제거 |
| 익스포트 | Web MIDI 불필요 — SMF 바이트 직접 생성 | 의존 없음 |
| 오디오 렌더 | `OfflineAudioContext` | **이미 하네스에서 쓰는 방식** |
| 백엔드 | 최소 REST + 오브젝트 스토리지 | 1인 운영. 복잡도 최소화 |
| 품질 게이트 | 기존 MCP 서버 확장 | 재사용 |

### 4.3 기술 원칙

1. **브라우저에서 되는 것은 브라우저에서 한다.** 오디오 렌더링·MIDI 생성은
   서버가 필요 없습니다. 서버는 보관과 자격증명만 맡습니다.
2. **외부 의존은 어댑터 뒤에.** 직접 호출을 코어에 넣지 않습니다.
3. **검증 자산을 재사용한다.** 새 품질 도구를 만들지 않고 `audio_measure` 를
   배치로 돌립니다.
4. **비동기 전환은 한 번에.** 프리셋 JSON 화 시 초기화 순서를 함께 정리합니다.

## 5. 보안 아키텍처 (SA)

현행은 인증·권한 개념이 없습니다. 서버가 생기는 순간 필요해집니다.

| 영역 | 위험 | 대응 |
|---|---|---|
| AI 서비스 자격증명 | 브라우저에 두면 유출 | **서버에만 보관**. 브라우저는 서버를 경유 |
| 프로젝트 데이터 | 무단 접근 | 사용자별 격리. 1인 운영이어도 계정 개념은 필요 |
| 생성 산출물 | 무단 다운로드 | 서명된 임시 URL |
| 유통 메타데이터 | 위변조 | 배포 이력 append-only |
| 외부 스크립트 | CDN 변조 | 로컬 번들 (TA §4.2) — 무결성 문제도 함께 해소 |

**지금 당장 필요한 조치는 없습니다.** 서버(T08)를 만들 때 함께 설계합니다.
다만 **AI 자격증명을 브라우저에 두는 설계는 절대 하지 않는다**는 원칙만
지금 고정합니다. 어댑터가 서버를 경유하도록 처음부터 그려야 합니다.

## 6. 전이 계획

### 6.1 아키텍처 전이 단계

| 단계 | 아키텍처 변화 | 되돌릴 수 있는가 |
|---|---|---|
| 1 | 코어에 송폼 엔진·시드 빌더 추가. 어댑터 계층 신설(MIDI만) | 예 — 기존 동작 불변 |
| 2 | 데이터 JSON 화 + 초기화 비동기 전환. AI·프롬프트 어댑터 추가 | **어려움** — 로드 구조가 바뀜 |
| 3 | 백엔드 도입. 저장소 클라이언트 추가 | 예 — localStorage 폴백 유지 |

**2단계가 되돌리기 어려운 지점입니다.** 그 전에 회귀 테스트(T12)를
갖춰야 합니다. ISP 로드맵에서 T12 를 2단계에 둔 이유입니다.

### 6.2 아키텍처 원칙 위반 감시

| 원칙 | 위반 징후 | 확인 방법 |
|---|---|---|
| 코어는 외부를 모른다 | `voice-*.js`·`sequencer.js` 에 fetch/URL 등장 | 정적 검사 |
| 자격증명은 서버에만 | 프런트 소스에 키 문자열 | 정적 검사 |
| 로드 순서 = 의존 순서 | 새 파일을 임의 위치에 삽입 | `ARCHITECTURE.md` 준수 검토 |
| 하네스는 앱 코드를 따라간다 | 보이스 수정 후 하네스 미수정 | 측정값이 앱과 어긋남 |

마지막 항목은 실제로 발생하는 문제입니다. `tools/` 의 하네스는 앱 코드를
**복사**해 쓰므로 보이스를 고치면 하네스도 같이 고쳐야 합니다.
`ARCHITECTURE.md` 에 명시돼 있으나 자동 검증 수단이 없습니다 — T12 대상.
