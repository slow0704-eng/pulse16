# 장르 프로파일 — genres/profiles/

`src/data/melody.js` 의 선율·리프·베이스 배정이 **왜 그렇게 됐는지**의 근거입니다.

| 폴더 | 다루는 것 |
|---|---|
| [../](../) `genres/*.md` | 악기 · 음색 · 수치 (사람이 읽는 자료) |
| [../../patterns/](../../patterns/) | 드럼 박자 |
| [../../melody/](../../melody/) | 선율 이론 · 계열별 어휘 |
| **genres/profiles/** | **프리셋 단위 선율 프로파일 (기계가 검사하는 자료)** |

---

## 1. 왜 프리셋 단위인가

`MELODY_KIT` 은 **하위분기** 키라 한 분기에 묶인 프리셋이 전부 같은 선율을
받습니다. `_build.js` 가 2026-08-17 에 `kit` 에서 끊어낸 것과 같은 상속이
선율 쪽에는 남아 있었습니다.

첫 배치에서 바로 걸렸습니다 — `Dancehall 계보` 6종이 한 분기인데,
선율로 보면 셋으로 갈립니다(아래 `09-I-dancehall.json`).
그래서 `melody.js` 에 `MELODY_KIT_PRESET` 을 두어 프리셋이 직접 정할 수
있게 했고, 그 판정의 근거를 여기에 둡니다.

---

## 2. 무엇을 적지 않는가

**아티스트·곡·앨범 이름을 적지 않습니다.** `genres/*.md` 의 레퍼런스 목록은
사람이 읽으라고 만든 자료이고 그대로 둡니다 — 문제가 되는 것은 그 이름을
생성 파이프라인 안으로 들이는 것입니다(`consulting/README.md`).

그래서 `evidenceBasis` 는 **형식이 강제됩니다**.

```
"evidenceBasis": "1980년대 후반 자메이카 킹스턴 · 10곡"
                  ^연대            ^서술           ^곡 수
```

`tools/ci/check-melody-profile.mjs` 가 이 형식을 검사합니다 —
**곡 제목이 들어갈 문법 자리를 없애 둔 것**입니다.
실제 곡의 선율을 옮겨 적지 않고, 여러 곡에서 뽑은 구조적 성질로 환원한 뒤
새로 만듭니다.

---

## 3. 가장 큰 실패는 «지어낸 차이» 다

357종을 전부 다르게 만들라고 하면 근거 없는 차이가 만들어집니다.

```
지금:        여럿이 한 풀을 공유 → 들으면 비슷함              (문제)
잘못된 개선:  357종이 357개 풀    → 근거 없는 난수            (더 나쁨)
옳은 개선:    진짜 다른 것만 다름                             (목표)
```

그래서 스키마에 **`axis: "none"`** 과 **`poolDecision: "share"`** 를 두었습니다.
«이 둘은 선율로 구분되지 않는다» 가 **정상적인 답**입니다.
첫 배치의 답도 6종 → 3풀이었지 6풀이 아니었습니다.

검사기는 이것을 **양방향**으로 봅니다.

```
거리 가까움  그런데  poolDecision="own"    → 지어낸 차이 의심
거리 멂      그런데  poolDecision="share"  → 진짜 차이를 뭉갠 것 의심
```

> ⚠ 거리 임계값은 **아직 없습니다.** 「얼마면 다른가」는 데이터가 쌓여야
> 정해집니다. 지금 숫자를 박으면 그것이 곧 지어낸 값입니다.
> 검사기는 거리를 **기록만** 하고 있습니다.

---

## 4. 파일

배치 하나 = 파일 하나입니다. 배치는 하위분기 단위이고, 검수에서 반려되면
되돌아가는 단위도 배치라 파일 단위가 그것과 같아야 diff 가 읽힙니다.

```
<계열번호>-<계열문자>-<하위분기슬러그>.json
09-I-dancehall.json     ← 계열 I(카리브) · Dancehall 계보 6종
```

## 5. 검사

```
node tools/ci/check-melody-profile.mjs
```

push·PR 마다 CI 가 같이 돌립니다(`.github/workflows/ci.yml`).
`meta.pool` 이 `melody.js` 의 실제 배정과 어긋나면 경고합니다 —
**근거와 데이터가 따로 놀지 않게** 하는 것이 이 폴더의 목적입니다.

## 대상은 357종이 아니라 338종입니다

프리셋은 357종인데 프로파일은 338종입니다. 나머지 19종은 «아직 안 한 것»이
아니라 **할 것이 없는 것**입니다. `tools/ci/check-melody-profile.mjs` 의 P8 이
매번 이 셈을 다시 해서 보여 줍니다.

| | 종수 | 왜 |
|---|---|---|
| 선율 없음 | 17 | Metal 10 · Punk 7. **건반을 안 쓰는 것이 그 장르의 성질**입니다. `melodyPoolFor()` 가 빈 배열을 돌려줍니다 — 빈 것이 곧 결론입니다 |
| 계열 `X` 예제 | 2 | `Play Along` · `Casio Cells`. **장르가 아닙니다** — Tone.js 의 샘플 로더가 도는지 보여 주려고 둔 데모입니다(`src/data/presets/12-example.js` 가 `drum-samples/CR78/*` · `casio/*` 를 실제로 내려받습니다). UI 에서 붉은 칩으로 따로 표시되는 것도 그래서입니다 |
| **대상** | **338** | |

> **2026-09-16 — 335 → 338.** 대표곡을 웹에서 검증해 보니 «메탈은 건반을 안 쓴다» 가
> 세 장르에서 틀렸습니다. Black Metal 2/4곡(Emperor 패드 · Burzum 신스 주선율),
> Power Metal 2/4곡(Stratovarius · DragonForce), Symphonic Metal 4/4곡(오케스트라·합창).
> 이 셋은 `MELODY_KIT_PRESET` 이 하위분기 `Metal:[]` 을 덮고 프로파일을 받았습니다.
> 나머지 Metal 10종(Heavy · NWOBHM · Thrash · Death · Doom · Sludge · Stoner 둘 ·
> Nu Metal · Metalcore)은 대표곡 크레딧에 건반이 없거나 인트로 한 번뿐이라 그대로입니다.
> Nu Metal 은 턴테이블·신스가 3/4곡에 있지만 **선율이 아니라 텍스처**라서 1마디 패드만 켰습니다.

둘째 줄이 중요합니다. 프로파일의 내용은 «이 세부장르의 구조적 성질 + 근거
(19xx년대 · N곡)» 인데, 데모 프리셋에는 장르도 없고 근거로 삼을 곡 무리도
없습니다. 그래도 칸을 채우려면 **없는 장르를 지어내야** 합니다. 그것이
이 작업에서 가장 하면 안 되는 일입니다(§2).

두 종은 계열 `X` 의 폴백 `['pop_aabb']` 을 그대로 받습니다(`melody.js`
`MELODY_KIT_CAT.X`). 장르 주장이 없으니 폴백이 맞습니다.
