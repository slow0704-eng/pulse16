PULSE·16 사용법 · 동작 원리 ← 도구로 돌아가기

브라우저에서 도는 16스텝 리듬·화성 생성기입니다. 서버도 로그인도 없고, 파일을 더블클릭해도 열립니다. 소리는 전부 그 자리에서 합성합니다 — 음원 파일을 재생하는 것이 아닙니다.

1. 30초 시작

  1. 프리셋 칩을 누릅니다. 맨 위 Pattern Library 에 357개가 있습니다. 장르 이름을 누르면 패턴·음색·템포·조성이 통째로 올라옵니다.
  2. Play 를 누릅니다 (Space).
  3. 그리드를 눌러 패턴을 고칩니다. 드래그하면 연속으로 찍힙니다.
  4. Variation 스위치를 켜면 루프가 돌면서 스스로 바뀝니다 — 틀어 놓고 듣는 것이 이 도구의 기본 사용법입니다.
첫 조작(아무 클릭·키 입력)에서 오디오 그래프를 미리 짓습니다. 그래서 Play 첫 클릭이 즉시 울립니다. 브라우저는 사용자 제스처 없이 소리를 못 내므로, 페이지를 열자마자 자동 재생되지는 않습니다.

3. 12개 트랙

드럼 7 + 음정 5 입니다. 트랙은 이름에 묶이지 않습니다 — 장르에 따라 tom 이 로그드럼·콩가·수르두가 되고, clap 이 탬버린이 됩니다.

6. 스스로 바뀌는 것들 (Variation)

이 도구의 핵심입니다. 각 항목은 루프 개수를 주기로 돕니다.

항목무엇이 바뀌나
Kit 셔플드럼 음색을 갈아끼웁니다
패턴 셔플패턴을 다른 프리셋으로 바꿉니다. 모드로 범위(같은 장르/계열/전체)를 정합니다
필인루프 끝에 필인을 넣습니다. 작은 것과 큰 것을 따로 돌립니다
선율 · 기타 리프16마디 선율 라이브러리에서 골라 연주합니다. 길이·레이어를 정합니다
곡 구조인트로 → 벌스 → 프리코러스 → 코러스 → 브릿지 → 브레이크 → 아웃트로. 섹션마다 트랙을 끄고 레벨을 바꿉니다
화성 진행마디마다 코드가 바뀌고, 건반·베이스·기타가 그 코드에 스냅됩니다
그루브장르별 스윙·벨로시티 느낌을 트랙마다 다르게 밀고 당깁니다
곡 구조를 켜면 트랙이 사라집니다 — 고장이 아닙니다. 인트로는 킥·베이스·하이햇만, 브레이크는 거의 전부 끕니다. keys2·gtr2 는 코러스에서만 켜집니다. 항상 다 듣고 싶으면 곡 구조를 끄십시오.

7. 동작 원리

7-1. 소리는 미리 만들어 두지 않습니다

음원 파일이 없습니다. 스텝이 올 때마다 오실레이터·필터·노이즈를 그 자리에서 조립해 울리고, 끝나면 해체합니다. 그래서 전체가 500 KB 남짓이고 음색을 무한히 비틀 수 있습니다.

7-2. 스케줄러 — 왜 setInterval 이 아닌가

자바스크립트 타이머는 수십 밀리초씩 흔들립니다. 그걸로 드럼을 치면 사람이 바로 알아챕니다. 그래서 오디오 시계를 씁니다 — 지금 울리는 것이 아니라 미래의 정확한 시각을 예약합니다.

onTick(t)  →  t 는 «이 스텝이 울려야 할 오디오 시각»
              지금이 아니라 조금 뒤(lookAhead)입니다.
              그 사이에 노드를 만들어 t 에 맞춰 예약해 둡니다.
              메인 스레드가 잠깐 늦어도 소리는 안 흔들립니다.

Tone.js 가 있으면 그 트랜스포트를, 없으면 내장 폴백 스케줄러가 같은 일을 합니다. 화면 갱신은 오디오와 분리돼 있어, 그림이 늦어도 소리는 정확합니다.

7-3. 노드 풀 — 만들고 버리지 않습니다

스텝마다 노드를 새로 만들면 가비지 컬렉터가 주기적으로 멈추고, 그 멈춤이 곧 글리치입니다. 게인·필터 노드를 풀에 넣고 돌려 씁니다. 화면의 nodes 숫자가 지금 살아 있는 노드 수입니다.

8. 합성 방식 네 가지

악기마다 «무엇이 소리를 내는가» 가 달라서 회로를 넷으로 나눠 씁니다.

① 감산 합성 — 신스·오르간·관악·스트링

오실레이터를 여러 개 쌓고 24 dB/oct 로우패스로 깎습니다. 필터가 음정을 얼마나 따라가는지(key scaling)와 몸통 공명이 «신스 패치» 와 «악기» 를 가릅니다. 몸통은 음정을 안 따라갑니다 — 통 크기는 고정이니까요.

② Karplus-Strong — 뜯은 현 (기타·베이스·민속 발현악기 35+7종)

짧은 지연선에 초기 변위를 넣고, 한 바퀴 돌 때마다 조금씩 깎으며 되먹입니다. 현이 실제로 하는 일과 같습니다.

뜯는 위치(β)  →  배음 널이 n = 1/β 에 섭니다
픽업 위치      →  또 다른 널. 두 널이 겹치면 배음에 구멍이 나므로 떨어뜨립니다
루프 저역통과  →  고역이 먼저 죽습니다 (굵은 현일수록 빨리)
복현(course)   →  한 음을 두 줄로. 두 줄이 절대 안 맞는 그 어긋남이 음색입니다
자와리(buzz)   →  시타르·샤미센. 진폭이 문턱을 넘는 동안만 접혀 부서집니다

라이브 지연선으로는 낮은 음을 못 냅니다(블록 크기 때문에 상한 187.5 Hz). 그래서 한 음을 통째로 버퍼에 구워 캐시합니다.

③ 비조화 가산 합성 — 때린 현·막대 (피아노·하프시코드·비브라폰·글로켄…)

피아노가 오르간처럼 안 들리는 이유는 비조화성입니다. 현이 뻣뻣해서 배음이 정수배보다 높습니다:

f_n = n · f0 · √(1 + B·n²)      B = 비조화 계수(저음일수록 큼)

배음 수십 개를 실시간 오실레이터로는 못 냅니다 — 역시 구워서 씁니다. 막대(마림바·글로켄)는 정수배가 아예 아니라 모드비를 직접 줍니다.

④ 병렬 모달 뱅크 — 몸통 공명 (밴조 가죽 헤드·시타르 박·스틸팬 통)

직렬 peaking EQ 는 기울기만 바꿀 뿐 스스로 울지 않습니다. 가죽 헤드가 받아 우는 것이 밴조의 정체성이라, 병렬 밴드패스를 가중합해 실제로 공진시킵니다.

9. 오디오 체인

보이스(오실레이터·노이즈·구운 버퍼) │ ├─ chan[트랙] ── 기타는 앰프+FX, 건반은 코러스를 거침 │ │ │ ├─ panner[트랙] ─┬─ 킥·베이스·건반 → duckNode(사이드체인) ─┐ │ │ └─ 그 외 ─────────────────────────────┤ │ └─ send[트랙] → sendMono → 컨볼루션 리버브 → 폭 확장 ──┤ │ ▼ │ mixBus │ │ │ busTrim │ ┌────────────────┬───────────────────┤ │ (본선) (Sub 병렬) (Exciter 병렬) │ 럼블 컷·글루컴프 저역 새추레이션 고역 배음 생성 │ └────────────────┴───────────────────┘ │ ▼ │ sumBus │ │ │ 마스터 새추레이션 → masterGain │ │ │ 리미터 │ │ │ 트루피크 실링(−3 dB 점근) │ ▼ └─────────────────────────────────── 스피커
트루피크 실링이 왜 따로 있나. 리미터는 어택이 4 ms 라 1 ms 급 킥 클릭을 못 잡습니다. 실측에서 정상 상태는 −3.5 dBFS 인데 트랜지언트가 그걸 3.5 dB 뚫고 나가 0 dBFS 를 넘었습니다. 그래서 샘플 단위로 즉시 듣는 소프트 클리퍼를 하나 더 뒀습니다. 문턱 아래는 손대지 않습니다 — 라우드니스를 지키는 자리입니다.

10. 프리셋이 정하는 것

프리셋 하나는 패턴 + 음색 + 템포 + 조성 + 노브값 한 벌입니다. 음색은 두 단계로 정해집니다.

  1. 프리셋 자신의 지정 — 있으면 무조건 이깁니다.
  2. 하위분기 배정표 — 프리셋이 안 적은 자리를 채웁니다. «Trap 계열» · «House 계열» · «쿠바» 같은 64개 분기마다 건반·기타·베이스·퍼커션·2번 트랙을 정해 둡니다.

프리셋이 늘어도 배정표는 안 늘어납니다. 특정 프리셋만 예외를 두고 싶으면 그 프리셋에 직접 적으면 됩니다.

트랩의 킥이 «808 Long» 이 아니라 «Tight» 인 것은 의도입니다. 베이스가 808(감쇠 긴 서브)인데 킥까지 1.6초 서브를 쓰면 저역이 충돌합니다. 둘 중 하나는 자리를 비켜야 합니다 — 트랩에서는 킥이 비킵니다.

11. 저장 · 오프라인

  • 자동 저장. 만지는 대로 브라우저에 저장되고, 다음에 열면 그대로 복원됩니다. 서버로 아무것도 보내지 않습니다.
  • 오프라인. 폰트와 오디오 라이브러리가 저장소 안에 들어 있어, 비행기 안에서도 전 기능이 동작합니다. 유일한 예외가 외부 드럼 샘플인데, 못 받으면 합성 엔진으로 알아서 되돌아갑니다.
  • 파일로 열기. 빌드 도구가 없습니다. HTML 파일을 더블클릭하면 그대로 돕니다.
