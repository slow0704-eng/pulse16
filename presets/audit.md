표기: 16스텝 그리드, 0부터 시작. `X`=강세, `x`=보통, `-`=없음.

## 2. 이번에 발견·수정한 오류

### Reggaeton 스네어 — 주석과 코드가 불일치

프리셋 위 주석은 "트레시요 3·6·11·14 검증 완료"라고 적혀 있는데,
바로 아래 `snare:` 실제 패턴은 **3·6·10·13**이었습니다.

```
수정 전  snare:'---x--x---x--x--'    → 스텝 3, 6, 10, 13   ✗
수정 후  snare:'---x--x----x--x-'    → 스텝 3, 6, 11, 14   ✓
```

**왜 3·6·11·14가 맞는가**
뎀보우 패턴은 각 박을 16분 4등분했을 때
1박의 **"a"**(3) → 2박의 **"&"**(6) → 3박의 **"a"**(11) → 4박의 **"&"**(14)에
떨어집니다. 10·13은 3박의 "&"와 4박의 "e"에 해당해 그루브가 한 스텝씩
앞으로 밀려 있었습니다.

같은 프리셋의 베이스는 원래부터 `0--0--0-5--5--3-` = 0·3·6·8·11·14로
**이미 올바른 트레시요 위치**였습니다. 즉 스네어만 베이스와 어긋나 있었습니다.

> 같은 오기가 이 문서의 이전 판에도 있었습니다. 표(3·6·11·14)가 맞고
> ASCII 표기가 틀렸던 것으로, 문서와 코드 양쪽을 수정했습니다.

## 3. 반영이 확인된 이전 지적 사항

### Trap ✅ 반영됨
| 항목 | 이전 | 현재 (mk16) |
|---|---|---|
| 템포 | 144 | **140** ✓ |
| 킥 엔진 | `deep` (감쇠 1.05초) | **`tight`** ✓ |
| 킥 튠 | −6 | **−1** ✓ |
| 베이스 엔진 | — | `s808`, gate 700, glide 52 ✓ |
| Sub | — | 68 ✓ |

```
kick   X-----x-X-----x-    tight, 튠 -1
snare  --------X-------    crack, 튠 +2
clap   --------x-------
chat   x-xxx-x-x-xxx-xx    tick, 튠 +2
bass   0-------5-------    s808, semi -3, gate 700, glide 52
```
킥이 짧아지고 808이 저역을 전담하는 구조가 완성됐습니다.

### Drum & Bass ✅ 반영됨
| 항목 | 이전 | 현재 (mk16) |
|---|---|---|
| 템포 | 172 | **174** ✓ |
| 고스트 스네어 | 없음 | **스텝 7·15 추가** ✓ |
| 하이햇 | 정박 8분 | **뒷박 8분** ✓ |

```
kick   X---------X-----    (0, 10)
snare  ----X--x----X--x    (4, 7고스트, 12, 15고스트)
chat   --x---x---x---x-    (뒷박 8분)
ohat   --------------x-
```

### Dembow → Reggaeton ✅ 개명됨
96 BPM은 레게톤 범위(85~100)에 정확히 들어갑니다.
뎀보우 본류는 115~130 BPM으로 별개 장르입니다.
→ [../genres/08-latin.md](../genres/08-latin.md) §2

### Afrobeat → Afrobeats ✅ 개명됨
프로그래밍 드럼 + 서브베이스 구성 = 복수형 Afrobeats가 맞습니다.
110 BPM도 범위(95~115)에 정확히 들어갑니다.
→ [../genres/10-african.md](../genres/10-african.md) §0

## 4. 스윙 노브의 실제 의미 (해결됨)

이전에 "미검증"으로 남겨둔 항목입니다. 코드에서 확인했습니다.

**코드 근거** (§6 오디오 그래프 · §8 파라미터 적용 · §10 시퀀서)
```js
Tone.Transport.swingSubdivision = '16n';
Tone.Transport.swing = knob('swing') / 100;

// 자체 스케줄러 경로 — fbLoop()
const six   = spb() * 0.25;                     // 16분음표 길이(초)
const shift = (fbStep % 2 === 1) ? six * (knob('swing')/100) * 0.66 : 0;
```

노브 0~100은 **Tone.js 스윙 파라미터 0~1**로 그대로 전달됩니다.
자체 스케줄러 경로에서는 홀수 스텝을 `16분 × (노브/100) × 0.66`만큼 뒤로 밉니다.

**이 계산에 따른 대응표**

| 노브 | 홀수 스텝 이동량 | 스윙 비율 | 해당 프리셋 |
|---|---|---|---|
| 0 | 0 | 50% (스트레이트) | Techno, Trap, DnB, Motorik |
| 8 | 0.053×16분 | 52.6% | Reggaeton |
| 12 | 0.079×16분 | 54.0% | House |
| 22 | 0.145×16분 | 57.3% | Disco Funk |
| 26 | 0.172×16분 | 58.6% | Afrobeats |
| 38 | 0.251×16분 | 62.5% | Boom Bap |
| 44 | 0.290×16분 | 64.5% | Lo-fi |
| **50** | 0.330×16분 | **66.7% (완전 셔플 = 2:1 셋잇단)** | — |
| 100 | 0.660×16분 | 83.3% (셋잇단 초과) | — |

**실무상 결론**
- **노브 50이 완전 셔플**입니다. 그 이상은 셋잇단을 넘어가는 과장된 스윙입니다
- 블루스 셔플·스윙 재즈를 근사하려면 **노브 50**
- 현재 프리셋 값들은 전부 50 이하라 음악적으로 타당한 범위에 있습니다
- UI 라벨이 `%`였는데 스윙 백분율(50~66%)과는 다른 단위라 혼동을 줬습니다.
  리팩토링에서 **`노브`로 표기를 바꾸고** 푸터에 설명을 추가했습니다

> 주의: 위 표는 자체 스케줄러 `fbLoop()`의 `×0.66` 계산에 근거합니다.
> `Tone.Transport.swing`을 쓰는 경로는 Tone.js 내부 곡선을 따르므로
> 두 경로의 체감이 미세하게 다를 수 있습니다. 설계 의도는
> 두 경로 모두 "노브 50 = 셋잇단"으로 보입니다.

## 5. 참고 — 문서 패턴과 프리셋 패턴의 차이

[../patterns/README.md](../patterns/README.md)의 패턴과
실제 프리셋이 다른 경우가 있습니다. **오류가 아니라 편곡 선택**입니다.

| 프리셋 | 문서 패턴 | 실제 프리셋 | 비고 |
|---|---|---|---|
| Boom Bap 킥 | 0, 6, 10 | 0, 3, 8, 12 | 둘 다 통용되는 붐뱁 변형 |
| Motorik 킥 | 0, 8 | 0, 4, 8, 12 (4·12는 약하게) | 노이! 계열에 두 형태 모두 존재 |
| Afrobeats 킥 | 0, 6, 10 | 0, 3, 6, 10, 13 | 실제 쪽이 더 촘촘한 신콥 |
| Lo-fi 햇 | 8분 전체 | 0,4,6,8,12,14 | 실제 쪽이 더 성김 |

문서 패턴은 "그 장르의 최소 골격", 프리셋은 "그 골격의 한 가지 구현"으로
읽으면 됩니다.

## 6. 남은 미검증 항목

- 각 장르의 **표준 킥/스네어 튜닝 값** — 수치화된 자료가 거의 없고
  대부분 "귀로 맞춰라" 수준. 현재 프리셋의 tune 값들은 상대적 균형만 맞춘 상태
- **`bcfg` 파라미터의 장르별 적정값** (blend, drive, xover, tone, exc, duck) —
  장르 자료로는 검증 불가. 청감 조정 영역
- Techno 하위 장르별 차이 (미니멀 / 인더스트리얼 / 디트로이트)
- House 하위 장르 (딥 / 테크 / 개러지)
- Lo-fi의 정확한 스윙 비율 — MPC 스윙 54~62% 언급이 흔하나 출처 불명확.
  현재 노브 44 = 약 64.5%로 그 범위보다 약간 강함

장르 레퍼런스 쪽의 미검증 항목은
[../genre-reference.md](../genre-reference.md) §신뢰도 참조.
