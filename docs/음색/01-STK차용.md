## 0. 왜 «가져왔는가»

**작업자가 청음을 할 수 없습니다.** 그 상태로 파라미터를 손으로 지어내면
«그럴듯한 숫자» 가 되고, 그건 음색이 아니라 난수입니다.

그래서 두 가지로만 채웠습니다.

1. **출처가 있는 값을 가져와 환산한다** — 아래 §1
2. **렌더해서 재고 기존 엔진에 맞춘다** — 아래 §3

`docs/mutable-차용.md` · `docs/tone-js-차용.md` 가 세운 규칙을 그대로 씁니다.

| 표기 | 뜻 |
|---|---|
| `소스확인` | 원본 파일을 통째로 내려받아 직접 읽음 |
| `환산` | 원본 단위(극반경·샘플당 감쇠)를 우리 단위(Q·초)로 바꾼 값. 식을 함께 적음 |
| `문헌` | 악기의 조율 범위·모드비 등 음향학에서 널리 쓰이는 값 |
| `실측` | 우리 코드로 렌더해서 잰 값 |

## 2. 환산식

STK 는 SR **44100** 기준이고 2극 공진기를 극반경으로 적습니다.

```
Q   = f·π / ((1−r)·44100)            극반경 r → 대역폭 → Q
T60 = 3 / (−log₁₀ d) / 44100         샘플당 감쇠계수 d → 진폭 1/1000 되는 시간(초)
FM 게인  fmGains_[i] = 0.933033^(99−i)    (FM.cpp 의 생성 루프)
        [99]=1.00 [95]=0.758 [92]=0.616 [90]=0.536
        [85]=0.379 [82]=0.308 [76]=0.203 [71]=0.143 [68]=0.116
```

> **안 주면 예전처럼 공비로 떨어뜨리므로 기존 9종의 소리는 한 샘플도 안 바뀝니다.**

**FM 계열 → KENG** (`wurli`·`fmlead`·`percflut`·`fmorgan`)

| 옮긴 것 | 안 옮긴 것 |
|---|---|
| C:M 비율(`setRatio`) · 감쇠/서스테인 시간(`setAllTimes`) · 모듈레이터 게인(환산) | **4-op 알고리즘의 연결 구조** |

⚠ **STK 는 4-오퍼레이터, 우리 엔진은 2-오퍼레이터 쌍입니다.** 그대로 못 옮깁니다.
지배적인 두 쌍만 남겼으므로 «STK 소리 그대로» 가 아니라 **«STK 비율을 쓴 우리 엔진»** 입니다.
코드 주석에도 같은 경고를 적어 두었습니다.

## 3. STK 에 없어서 다른 근거로 채운 것

STK 는 물리모델 라이브러리라 **드럼머신 음색과 막울림(드럼헤드)이 없습니다**
(`Drummer` 클래스는 샘플 재생입니다). 그 계열은 아래 근거로 채웠습니다.

| 계열 | 수 | 근거 |
|---|---|---|
| 킥·스네어·클랩·하이햇 | 21 | 각 드럼머신의 **회로 특성**(808 은 브리지드-T 라 감쇠가 길고 클릭이 없음, 909 는 피치가 빨리 떨어지고 클릭이 큼) + `실측` 레벨 정합 |
| 톰(세계 막울림) 9 | 9 | ① 악기별 **문헌상 조율 범위** 중앙값 ② **이상적 원형막의 베셀 0점 모드비** 1 : 1.593 : 2.136 : 2.296 : 2.653 : 2.918 |
| 타현·타봉 6 | 6 | **자유단 막대의 횡진동 모드비** 1 : 2.756 : 5.404 : 8.933 : 13.34 (오일러-베르누이 자유-자유 해). 실로폰 3:1 · 마림바 4:1 로 2번 모드를 깎는 것까지 반영 |
| 관악 6 | 6 | **관의 음향학** — 닫힌관(클라리넷·팬플루트)은 홀수 배음만, 열린관은 정수 배음 전부, 금관은 세기에 따라 밝아짐 |
| 발현악기 18 | 18 | 뜯는 위치(β)·현 재질·통 재질에서 lpF·t60 결정. 복현 악기는 `course` |
| 현 베이스 7 · 합성 베이스 7 | 14 | 현 감김 방식(라운드/플랫/테이프)과 오실레이터 스택 |

⚠ **찰현(bowed) 악기는 넣지 않았습니다.** `voice-gtr.js` 의 `bowed` 경로는
`fiddleVoice()` 하나로 고정이라 파라미터를 안 받습니다 — 첼로·얼후를 넣어도
피들과 **똑같은 소리**가 납니다. 파라미터화가 먼저입니다.

## 4. 레벨 정합 — 귀 대신 계측

새 엔진의 `amp` 는 환산이 아닙니다(STK 의 GAIN 은 자기네 신호 경로 기준).
**렌더해서 재고 기존 엔진의 중앙값에 맞췄습니다.**

> ⚠ 한 방 측정으로는 못 맞춥니다. 노이즈로 여기하는 타악기는 **회차 편차가 최대 8.4 dB**
> 였습니다(`rocks` 를 두 번 재서 −12.1 / −4.9 dB). 엔진마다 **10회 렌더해 평균**냈습니다.

수렴 결과(perc, 기존 9종 중앙값 피크 −12.1 dB):

| | 1차 | 보정 후 |
|---|---|---|
| `sekere` | −19.7 (−7.6) | −12.5 (−0.1) |
| `bamboo` | −24.8 (−12.7) | −11.5 (−1.0) |
| `angklung` | −24.0 (−11.9) | −12.7 (+0.2) |
| `sticks` | −3.0 (+9.1) | −12.3 (−0.2) |

**핑크 노이즈 함정을 한 번 밟았습니다** — `dark` 하이햇을 `pink:1` 로 두고 amp 를
화이트 기준(0.55)으로 남겼더니 실측이 **14.3 dB** 낮았습니다. `shaker`·`brush` 주석이
경고해 둔 바로 그 함정입니다. ×5.16 해서 2.84 로 고쳤습니다.
