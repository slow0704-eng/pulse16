# 락 레퍼런스 대조 — 실제 음원과 같은 자로 재기

작성: 2026-10-13 · 대상: `Grunge` · `Shoegaze` · `Heavy Metal` · `Pop Punk`
성격: **그때의 기록**입니다(CLAUDE.md ⑰). 현행 값은 `src/data/presets/01-rock.js` 가 정본입니다.

---

## 0. 한 문단 요약

> 장르마다 대표곡 3곡(`genres/01-rock.md` «대표곡» 표에서 웹 검증이 끝난 곡)을 받아
> **Demucs 로 drums · bass · other · vocals 로 갈랐고**, 우리 프리셋은 트랙을 하나씩 솔로로
> 녹음해 같은 네 묶음으로 접어 비교했습니다. 네 장르 모두에서 같은 결함이 나왔습니다 —
> **리듬 기타가 모노**(기타 스템 사이드 −16~−18 dB, 레퍼런스 −4.8~0.0 dB)이고
> **드럼의 중역~프레즌스가 4~10 dB 모자라며 초저역이 3~7 dB 많습니다.**
> 기타 더블 트래킹(ADT)을 새로 만들고 네 프리셋의 스네어·버스 저역 값을 고쳐
> 반주 7대역의 |Δ| 합계를 20.5→19.0 · 23.5→19.8 · 32.4→22.4 · 31.6→22.1 dB 로 줄였습니다.
> **남은 가장 큰 어긋남은 8~16 kHz(air) 과다**입니다. 이튿날 트랙별로 나눠 보니 그 일부는
> **2번 기타가 앰프를 아예 안 거치던 결함**이었고(§6, 고침), 나머지는 스네어·햇 보이스입니다(§5).

⚠ **보컬을 빼지 않고 믹스끼리 비교하면 틀린 결론이 나옵니다.** 처음 믹스끼리 잰 표는
«500 Hz~2 kHz 가 5~10 dB 모자라다» 고 말했지만, 스템으로 갈라 보니 그 차이는 보컬이었습니다
(반주끼리는 −0.6~−2.4 dB). 그대로 기타 EQ 를 올렸다면 근거 없는 수정이 됐을 것입니다.

## 1. 절차 — 다시 돌리려면

받은 음원과 스템은 **저장소에 두지 않습니다**(스크래치 폴더에서만 씁니다).

| 단계 | 도구 | 비고 |
|---|---|---|
| ① 음원 받기 | `yt-dlp -x --audio-format wav` | 공식·Topic 채널 업로드만. 재업로드는 원본 마스터와 다를 수 있다 |
| ② 가운데 90초 | `ffmpeg -ss <길이×0.35−30> -t 90` | 코러스가 들어오는 구간. CPU Demucs 가 곡당 약 2분 |
| ③ 스템 분리 | `demucs -n htdemucs` | `uv tool install --python 3.12 demucs --with torch==2.5.1 --with torchaudio==2.5.1 --with soundfile` |
| ④ 우리 쪽 녹음 | `node tools/ref/render-solo.mjs <폴더> 10 <프리셋>…` | 곡 구조를 끄고 트랙별 솔로 + 전체 |
| ⑤ 층 구조 | `python tools/ref/layers.py ref <스템폴더>` · `… ours <폴더> <프리셋>` | |
| ⑥ 표 | `python tools/ref/cmp_layers.py <작업폴더> <우리.jsonl>` | |
| (믹스 하나) | `python tools/ref/feat.py <wav>` | LUFS·LRA·트루피크·대역·폭·템포 |

파이썬은 librosa·scipy·soundfile 이 든 환경이면 됩니다(이번에는 `beatlyzer` 의 uv 환경을 썼습니다).
받은 파일은 신뢰하지 않는 데이터이므로 `python -I` 로 돌립니다.

**읽는 법** — 대역 값은 «그 묶음 안에서 그 대역이 차지하는 몫»(dB, 합이 0 dB)입니다.
`side` 는 사이드/미드 파워비, `lvl` 은 반주(drums+bass+other) 합 대비 묶음 레벨입니다.
레퍼런스는 3초 RMS 상위 50% 구간(몸통)만 씁니다.

### 측정의 한계 — 숫자를 쓰기 전에

- **YouTube 음원은 손실 압축**입니다. 16 kHz 위는 믿지 않습니다(대역을 16 kHz 에서 끊었습니다).
- **Demucs 는 베이스의 고역을 other 로 보냅니다.** 그래서 «베이스 2 kHz 위가 우리 쪽이
  +7~+26 dB» 라는 수치는 **근거로 쓰지 않았습니다** — 분리기의 성질일 수 있습니다.
- 솔로 녹음은 트랙마다 **마스터 체인(글루 컴프·리미터)을 따로** 지납니다. 묶음 합은 근사입니다.
- 레퍼런스 마스터는 1970~2007년에 걸쳐 있고 리마스터 여부를 확인하지 않았습니다.
  **라우드니스(LUFS)는 비교하지 않았습니다** — 우리 −10~−14 LUFS, 레퍼런스 −7~−15 LUFS.

## 4. 바꾼 것

| 무엇 | 어디 | 근거 |
|---|---|---|
| **리듬 기타 더블 트래킹(ADT)** 을 새로 만듦 — 사본을 11 ms 늦추고 0.5 Hz 로 ±1.5 ms 흔들어 원음은 왼쪽, 사본은 오른쪽(±0.85, 폭 노브를 따름). 둘 다 −3 dB 라 파워는 그대로 | `graph.js` 채널 스트립 · `params.js` `applyWidth`·`setGtrDbl` · 프리셋 칸 `gdbl` | 12곡 전부 other 스템이 넓다(§3). Shoegaze 는 텍스트 출처도 같은 말 — `genres/01-rock.md` «massively overdubbed» · «12현 두 대» |
| 네 프리셋에 `gdbl:1` | `01-rock.js` | 위 |
| 스네어 0.68 → **0.96**(+3 dB) | 네 프리셋 `lvl.snare` | 드럼 mid~pres 가 4~10 dB 모자람. +6 dB 안도 재 봤으나 air 가 더 커져 |Δ| 합이 같거나 나빴다 — +3 dB 가 네 장르 모두에서 더 작았다 |
| 버스 저역 증강 `sub` 56 → **20** | 네 프리셋 `bcfg.sub` | 반주 sub 과다. 다만 효과는 1~3 dB 뿐이었다 — 초저역의 대부분은 **보이스 자체**에서 나온다(§5) |
| **프리셋 레벨 누수 수정** — 프리셋이 적지 않은 칸은 초기값으로 되돌린다 | `build.js` `applyPresetLvl` · `state.js` `LVL_INIT` | 예전에는 적힌 칸만 바꿔서 Heavy Metal(`gtr 0.62`) 다음에 `gtr` 칸이 없는 프리셋을 부르면 0.62 가 남았다. 드럼 칸을 프리셋 레벨에 처음 넣으면서 이것이 스네어 +3 dB 를 다른 모든 프리셋으로 옮길 판이었다 |

`gdbl` 이 없는 프리셋은 예전과 같습니다 — 사본 게인 0, 원음 게인 1, 기타 팬 그대로(브라우저에서 확인).

## 5. 안 바꾼 것 — 다음에 할 일 (영향 큰 순)

1. **스네어·햇이 지나치게 밝다.** 스네어 엔진 일곱(`body`·`crack`·`tight`·`fat`·`rimshot`·`piccolo`·
   `lofi`)을 솔로로 재니 `lofi` 를 뺀 여섯의 스펙트럼 무게중심이 **7.5~8.0 kHz** 였습니다. 8 kHz 위가
   가장 큰 대역이고, 엔진을 바꿔도 같습니다 — 와이어 노이즈 설계가 공통입니다. 반주 air 과다의 주원인이고,
   스네어를 올리면 그만큼 커집니다. **보이스 수정이므로 모든 장르에 걸리고, 공표된 스네어 스펙트럼과
   대조한 뒤에 해야 합니다**(CLAUDE.md ⑧).
2. **킥에 비터 클릭이 없다.** 킥 엔진 넷(`punch`·`wood`·`tight`·`deep`)이 전부 사인 스윕 구조라 2 kHz 위가
   −59~−65 dB 입니다. `wood`(Acoustic)로 바꿔도 드럼 sub 가 0.5 dB 밖에 안 변했습니다.
   락의 킥은 어쿠스틱이고 비터가 2~5 kHz 를 채웁니다.
3. **현 베이스의 기음이 너무 크다.** 베이스 sub 가 레퍼런스보다 +4~+10 dB 입니다(Pop Punk 만 +1.6).
   `stringBass` 는 Blend·X-Over 를 안 쓰므로 원인은 현 모델의 기음 대 배음 비율입니다.
   이것도 모든 장르의 pick·finger 베이스에 걸립니다.
4. **드럼 스테레오가 좁다**(사이드 −23~−29 dB, 레퍼런스 −9~−12). 드럼 트랙 팬은 전 장르 공통값
   (`config.js` TRACKS)이라 프리셋으로 못 고칩니다. 오버헤드처럼 킷 전체를 벌리는 구조가 필요합니다.
5. **나머지 락 프리셋.** `sub:56` 은 전 장르 프리셋이 같은 틀에서 복사한 값이고 이유를 적은 문서가
   없습니다. 이번에 잰 넷에서는 측정이 반대로 말했지만, **재지 않은 장르에 옮기지 않았습니다**
   — 같은 절차(§1)로 재고 옮길 것.

## 6. 2026-10-14 — 2번 기타가 앰프를 안 거치고 있었다

§3 의 air 과다를 트랙별로 나눠 보니(솔로 녹음의 대역 몫) **스네어·햇보다 먼저 2번 기타**가 걸렸습니다.
기타·건반 묶음의 air 가 레퍼런스보다 +8~+15 dB 였는데, 1번 기타는 air 몫이 −29~−50 dB 인 반면
**2번 기타는 −14~−19 dB** 였습니다.

원인은 `guitarVoice2()` 가 현 소리를 `chan.gtr2` 로 **바로** 보내던 것입니다(«앰프를 안 거치고 2번 채널로»).
그래서 엔진 이름이 `hi`·`crunch`·`fuzz` 여도 2번 기타에서는 왜곡도, 5 kHz 위를 자르는 캐비닛도 없는
생 현 소리였습니다. `clean`·통기타·밴조의 몸통도 마찬가지로 빠져 있었습니다 — **장르와 상관없이**
2번 기타가 울리는 모든 프리셋에 걸린 결함입니다.

**고친 것** — `graph.js` 의 기타 앰프·몸통 정의를 «출구를 받는 함수»(`GAMP`)로 바꿨습니다.
1번 기타는 예전처럼 부팅 때 전부 `chan.gtr` 로 만들고, 2번 기타는 **처음 쓰는 엔진만** `chan.gtr2` 로
한 벌 만듭니다(`gtr2Amp`, `voice-gtr.js`). 1번 기타의 소리는 그대로입니다(솔로 대역 몫 차이 ±1 dB, 실행마다 흔들리는 폭 안).
기타 버스 이펙트(와·페이저·코러스)는 여전히 1번 기타에만 걸립니다.

**비용** — 음마다 앰프 체인에 `connect` 하는 값이 2번 기타에도 붙습니다. 이 기계에서
Heavy Metal 재생 중 `guitarVoice2` 한 번이 중앙값 0.8 → 1.4 ms, 상위 10% 1.5 → 4.7 ms 였습니다(1번 기타와 같은 수준).
`docs/perf/01` §3-2 의 8~12 ms 보다 훨씬 작습니다. 그 문서 ⑤의 «상주 입력 게인» 안은 재 보니 소용이 없었습니다 —
`BufferSource → 상주 게인(앰프에 연결됨)` 이 `게인 → 앰프` 와 같은 1.0~1.1 ms 였습니다. SAC 의 비용은 «잇는 노드» 가 아니라 **하류 그래프의 크기**를 따릅니다.

**결과** — 반주 7대역 |Δ| 합(§3 과 같은 자). ⚠ **같은 설정을 두 번 녹음해도 ±2 dB 흔들립니다**
(선율·휴머나이즈가 실행마다 다름). 그래서 Heavy Metal·Pop Punk 는 전후를 두 번씩 쟀습니다.

| | Grunge | Shoegaze | Heavy Metal | Pop Punk |
|---|---|---|---|---|
| \|Δ\| 합 전 | 19.0 | 19.8 | 22.4 · 20.5 | 22.1 · 23.7 |
| \|Δ\| 합 후 | 17.6 | 19.6 | **18.0 · 18.0** | 24.5 · 22.7 |
| 기타·건반 air Δ 전 → 후 | +15.2 → +13.1 | +14.2 → +13.6 | +8.1·+8.7 → **−12.4·−12.6** | +13.8·+14.7 → **+3.7·+1.8** |
| 반주 air Δ 후 | +6.4 | +5.0 | +10.8 · +10.7 | +8.9 · +9.9 |

- Heavy Metal 은 분명히 나아졌고, Pop Punk 는 합이 흔들리는 폭 안입니다. Pop Punk 의 기타 air 는 거의 맞았지만
  **반주 air 는 그대로**입니다 — 거기서는 드럼(스네어·햇)이 air 를 쥐고 있다는 뜻이고, §5-1 이 여전히 1순위입니다.
- Grunge·Shoegaze 는 2번 기타가 작게 깔려 거의 안 변했습니다. 이 둘은 **1번 기타의 air 몫이 −29 dB**(다른 둘은 −47~−50)
  인데, 1번 기타가 각각 `wah`·`fuzz` 입니다. 원인은 아직 재지 않았습니다(아래 6).
- 다른 계열 여섯(Eurodance·Funk·Jazz Fusion·Honky-tonk·Cumbia·House)의 전체 믹스를 전후로 재니
  라우드니스 ±0.5 LU, 트루피크 −1.6 dBFS 이하로 안전했습니다. 그 장르들의 소리 판단은 레퍼런스 없이 하지 않았습니다.

§5 에 덧붙이는 할 일:

6. **Grunge·Shoegaze 의 1번 기타 air 가 크다**(몫 −29 dB, 레퍼런스 기타 스템 −43 dB). Grunge 는 `wah`
   (`amp_cru` 뒤에 버스 와), Shoegaze 는 `fuzz`(`amp_fuzz`, 이펙트 없음)라 원인이 하나라고 단정할 수 없습니다.
   `amp_fuzz` 의 캐비닛 로우패스가 6.2 kHz 로 가장 높다는 것까지만 봤고, 재지 않았습니다.

### 검증하지 않은 것

- 섹션별(곡 구조 켠 상태) 비교는 하지 않았습니다 — 솔로 녹음은 곡 구조를 끈 루프입니다.
- 템포·키는 비교하지 않았습니다. 레퍼런스 BPM 은 이미 대표곡 표(위키백과)에 있고, librosa 의 템포
  추정은 하프·더블타임을 자주 헷갈렸습니다(우리 Heavy Metal 140 BPM 을 112 로 읽음).
