**[죽음]** 앱이 못 쓰게 된다 · **[불가]** 기능이 안 된다 · **[거슬림]** 쓸 수는 있다.

### R1 · 저장본에 `bass` 가 없으면 «복원 성공» 뒤에 계속 죽는다 — **[불가] · 고착**

`loadState()` 는 `drums` 만 `fillTracks()` 로 메우고 `bass` 는 **날것 그대로 대입**합니다.

```js
// src/ui/edit.js:104  (restoreSnap 도 :32 에서 같은 코드)
banks[i].drums = fillTracks(b.drums);  banks[i].bass = b.bass;   // ← bass 무방비
```

`b.bass` 가 `undefined` 여도 `loadState()` 는 `true` 를 돌려주므로
화면에는 «이전 상태를 복원했습니다» 가 뜹니다. 그리고 시퀀서가
`P.bass[i]` 를 읽는 순간(`src/seq/sequencer.js:147`)부터 매 스텝 죽습니다.

**더 나쁜 점**: 그 뒤 아무 편집이나 하면 `markDirty()` → `saveState()` 가
같은 깨진 상태를 **다시 저장**합니다(`JSON.stringify` 는 `undefined` 키를
그냥 빼 버리므로 손상이 그대로 재생산됩니다). 새로고침해도 되풀이됩니다 —
사용자가 «저장 지움» 버튼을 찾아내기 전까지 앱이 계속 고장난 채로 남습니다.

#### 재현 절차

1. 앱을 연다.
2. 개발자도구 콘솔에 붙여넣는다:
   ```js
   const S = 16, D = ['kick','snare','clap','chat','ohat','tom','perc'];
   const b = () => ({drums: Object.fromEntries(D.map(d => [d, new Array(S).fill(0)]))});
   localStorage.setItem('pulse16.mk16.v1', JSON.stringify({
     v:1, banks:[b(),b(),b(),b()], bank:0, src:{}, eng:{}, probT:{},
     mute:{}, lvl:{}, rootNote:9, scaleName:'Minor Pentatonic', baseOct:24,
     knobs:{}, sels:{}, panels:{}
   }));
   ```
3. 새로고침한다 → 오른쪽 위에 «이전 상태를 복원했습니다» 가 뜬다.
4. Play 를 누른다.

**관측**: `TypeError: Cannot read properties of undefined (reading '0')` 이
스텝마다 쏟아진다(측정값 25건/4초). 뱅크 전환(`switchBank`)도 같은 예외로 죽는다.
베이스 트랙이 통째로 안 나온다.

#### 트레이드오프

`bass` 하나만 막으면 다음에 트랙이 늘 때 또 같은 일이 납니다.
반대로 «모든 값을 스키마로 검증» 하면 코드가 크게 늘고, 진짜 버그가
«기본값으로 조용히 대체» 뒤에 숨습니다.

**판단**: 중간을 택합니다. `fillTracks()` 가 이미 «트랙이 늘어도 안 깨지게»
라는 **이름값을 하고 있으니**, 그 함수를 뱅크 전체를 메우는 것으로 넓히면
방어 코드는 5줄 늘고 앞으로 트랙이 늘어도 자동으로 커버됩니다.
값의 «내용»(숫자 범위 등)까지는 검증하지 않습니다 — 거기까지 가면 비용이
효용을 넘습니다.

#### 구현 명세

- `src/ui/edit.js` — `fillTracks(drums)`(16행)를 `fillBank(b)` 로 넓힌다.
  `drums` 는 지금처럼 `TRACK_IDS` 로 메우고, 여기에 `bass`·`gtr`·`gtr2` 는
  `-1` 채움, `keys`·`keys2` 는 `0` 채움을 **`Array.isArray` 검사와 함께**
  추가한다(현재 `b.keys || …` 식의 `||` 검사는 «배열이 아닌 값»은 못 거른다).
- 같은 파일 `loadState()`(104행)와 `restoreSnap()`(32행) 두 곳을 모두
  `fillBank(b)` 호출로 바꾼다 — **실행취소 스냅샷도 같은 구멍이 있다.**

### R2 · 내장 폴백 스케줄러가 백그라운드 탭에서 무너진다 — **[불가] · 조건부**

`start()` 는 Tone 이 없을 때 `setInterval(fbLoop, 25)` 로 돌고,
`fbLoop()` 는 **140 ms 앞까지만** 채웁니다.

```js
// src/seq/sequencer.js:531
function fbLoop(){
  while(fbNext < ctx.currentTime+0.14){ … }      // 앞보기 140 ms
}
// src/seq/sequencer.js:594
fbTimer = setInterval(fbLoop, 25);               // 메인스레드 타이머
```

크롬은 숨은 탭의 `setTimeout`/`setInterval` 을 **최소 1초**로 조입니다.
1000 ms > 140 ms 이므로 매 호출 사이에 **860 ms 의 빈 구간**이 생기고,
다음 호출 때 밀린 스텝이 «이미 지나간 시각» 으로 한꺼번에 예약됩니다.
Web Audio 는 과거 시각을 즉시 재생으로 처리하므로 — 소리로는
**1초에 한 번 4~5개 음이 뭉쳐 튀고 나머지는 침묵** 입니다. 박자가 사라집니다.

Tone 경로는 무사합니다(워커 기반 티커라 조임을 안 받음). 즉 이 결함은
**Tone.js CDN 이 죽은 사용자에게만** 나타납니다 — 즉 R2 는 R1 과 달리
«폴백의 폴백» 문제입니다.

#### 재현 절차

실제 백그라운드 탭은 자동화로 재현하지 못했습니다(§1.6). 아래는
**크롬이 숨은 탭에 하는 일을 그대로 모사**하는 절차입니다.

1. Tone.js 없는 상태를 만든다 — `pulse16-mk16.html` 의 cdnjs `<script>`
   를 없는 URL 로 바꾼 사본을 같은 폴더에 두고 그것을 연다.
   (또는 개발자도구 Network 탭에서 `cdnjs.cloudflare.com` 을 차단하고 새로고침)
2. 상태표시줄이 «내장 스케줄러로 실행» 인지 확인하고 Play.
3. 콘솔에 붙여넣는다:
   ```js
   window.__log=[]; const o=voicesAt;
   voicesAt=(i,t)=>{ __log.push([t, ctx.currentTime]); return o(i,t); };
   const si=setInterval; setInterval=(f,d,...a)=>si(f,Math.max(d||0,1000),...a);
   clearInterval(fbTimer); fbTimer=setInterval(fbLoop,25);
   ```
4. 10초 기다린 뒤:
   ```js
   __log.filter(([t,now]) => t < now).length + ' / ' + __log.length
   ```

**관측**: `48 / 58` (83%). 최대 지각 **849 ms**. 소리로도 박자가 무너집니다.
조임을 풀면 즉시 `0 / 30` 으로 회복됩니다.

**참고 — 대조군**: 같은 절차를 Tone.js 가 살아 있는 판에서 하면 `0 / 59` 입니다.

#### 트레이드오프

세 가지 길이 있습니다.

1. **앞보기를 늘린다** (140 ms → 1.5 s). 가장 싸다(상수 하나).
   대신 BPM·스윙·패턴 변경이 최대 1.5초 늦게 반영돼 «노브가 굼뜬»
   악기가 된다 — 이 앱의 핵심 가치를 깎는다.
2. **`visibilitychange` 에서만 앞보기를 늘린다.** 보이는 동안은 지금 그대로,
   숨으면 1.5초로. 코드 6~8줄. 보이는 동안의 반응성을 전혀 안 깎는다.
3. **워커 타이머로 옮긴다.** 근본 해결이지만 폴백 경로에 워커를 하나
   더 얹는 것이고, 폴백은 «Tone 이 죽었을 때만» 도는 길이다.

**판단**: **2번.** 이 경로를 밟는 사용자는 이미 CDN 장애를 겪는 소수이고,
그중 «탭을 옮겨 두고 계속 듣는» 사람은 더 적습니다. 근본 해결(3번)에
쓸 복잡도를 여기에 붓는 건 과합니다. 다만 «숨었을 때만 굼뜬 대신 안 끊긴다»
는 교환은 명백히 이득이므로 2번은 넣을 값어치가 있습니다.

#### 구현 명세

- `src/seq/sequencer.js` — 앞보기 `0.14` 를 상수 `let fbAhead = 0.14` 로 빼고
  `fbLoop()`(531행)이 그 변수를 쓰게 한다.
- `src/ui/events.js` 의 이벤트 묶음 끝에 추가:
  ```js
  addEventListener('visibilitychange', () => {
    if(HAS_TONE) return;               // Tone 경로는 조임을 안 받는다
    fbAhead = document.hidden ? 1.5 : 0.14;
  });
  ```
- `src/audio/graph.js:470` 의 `setInterval(sweep,120)` 도 같은 조임을 받는다.
  `sweep` 이 늦어도 소리는 안 나가지만 `retireQ` 가 길어진다(측정상 최대
  553개, 상한은 있음). **지금은 손대지 않아도 된다** — 재생 속도에 비례해
  묶이므로 무한히 자라지 않는다.

### R3 · `liveNodes` 계수기가 틀렸다 — **[거슬림] + 진단 수단 상실** — ✅ **시험 중 고쳐짐**

> **상태**: 성능 담당이 독립적으로 같은 결함을 찾아 `src/core/util.js` 의
> `sweep()` 을 `if(kind==='gain' || kind==='bq') liveNodes--;` 로 고쳤습니다
> (아래 §구현 명세에서 제가 권고한 것과 같은 방식입니다).
> **재확인**: 200 BPM · 45초(37루프) 재생 후 `liveNodes = 399`, 화면 표시도
> `nodes 399` — 양수이고 안정적입니다. 아래 기록은 «왜 그 한 줄이 필요한지» 와
> 회귀 시험 절차로 남겨 둡니다.

`sweep()` 은 `retireQ` 에서 걷어내는 **모든** 항목마다 `liveNodes--` 를 합니다.
그런데 `liveNodes++` 는 `acqGain()`/`acqBQ()` 두 곳뿐입니다.

```js
// src/core/util.js
function acqGain(){ … liveNodes++; return g; }     // 110
function acqBQ(…){ … liveNodes++; return b; }      // 114
function sweep(){ … liveNodes--; … }               // 129 ← 종류를 안 가림
```

`retire(node,'x',at)` 로 등록되는 것들 — `shaperNode()`, `tapNoise()`,
`tapPink()`, `tapMetal()`, 그리고 `voice-bass.js`/`voice-gtr.js`/
`voice-keys.js`/`voice-drum.js` 의 «참조 정리용» 클로저 약 10곳 — 은
**늘린 적이 없는데 줄이기만** 합니다.

**측정으로 확정했습니다.** 45초(37루프) 뒤:

| 값 | |
|---|---|
| `liveNodes` | **−1977** |
| `'x'` 종류 retire 횟수 | 2530 |
| `liveNodes + x회수` | **553** |
| 그때 `retireQ.length` | **553** ← 정확히 일치 |

즉 오차는 정확히 `'x'` retire 횟수만큼입니다. 3분 돌리면 **−7751** 까지 갑니다.

**두 가지가 문제입니다.**
① 사용자 화면(`src/ui/meters.js:94`)에 `nodes -1980` 이 그대로 찍힙니다.
② 과제가 «노드가 새는지 `liveNodes` 추이로 보라» 고 했는데,
   **그 계기판 자체가 고장나 있어** 진짜 누수를 볼 수 없습니다.

#### 재현 절차

1. 앱을 연다. Play.
2. 30초쯤 기다린다.
3. 오른쪽 위 상태표시줄의 `nodes …` 숫자를 본다.

**관측**: 음수. 시간이 갈수록 단조 감소.

#### 별도 확인 — 진짜 누수는 없다

계기판을 못 믿으므로 따로 쟀습니다. 220 BPM · 선율·필인 ON · 3분(140루프):

- JS 힙: 19.6 ~ 45.5 MB 사이 진동, **단조 증가 없음**
- `retireQ`: 160 ~ 303, `pool`: 상한(64+64) 안
- 원시 노드 생성량(루프당): 오실레이터 72.9 · 게인 12.0 · 스테레오패너 15.7 ·
  버퍼소스 12.6 · 웨이브셰이퍼 5.6 · 바이쿼드 0.7

**결론: 누수 없음.** 다만 패너·웨이브셰이퍼·버퍼소스는 풀을 안 타서
GC 압력이 됩니다(설계상 게인·바이쿼드만 풀 대상). 지금 성능 문제는
관측되지 않았으므로 **손대지 말 것을 권합니다.**

#### 트레이드오프

계수기를 고치는 길은 둘입니다.

1. **`sweep()` 이 종류를 가려 `'x'` 는 안 깎게 한다** — 1줄.
   `if(kind==='gain'||kind==='bq') liveNodes--;`
2. `'x'` 등록 때도 `liveNodes++` 를 한다 — 등록 지점이 14곳이라 손이 많이 가고
   또 빠뜨릴 여지가 생긴다.

**판단**: **1번.** `liveNodes` 의 뜻은 «풀에서 나가 있는 노드 수» 이므로
증가 지점과 감소 지점을 같은 종류로 맞추는 것이 이름값에도 맞습니다.
방어 코드가 아니라 **버그 수정**이므로 트레이드오프랄 것이 없습니다.
→ 실제로 이 방식으로 수정됐습니다.

한편 «음수면 0으로 보정해 표시» 같은 **화면 쪽 가림막은 넣지 마십시오.**
그건 계기판을 고치는 게 아니라 계기판에 테이프를 붙이는 것이고,
다음에 진짜 누수가 났을 때 그것도 같이 가려 버립니다.
(현재 `src/ui/meters.js` 는 손대지 않은 채 정상값이 나오고 있습니다 — 옳습니다.)

#### 회귀 시험 항목

`retire(node,'x',at)` 를 쓰는 자리가 새로 생길 때마다 이 계수기가 다시
어긋날 수 있습니다. 새 `'x'` retire 를 추가하는 변경이 오면:

1. 200 BPM 으로 45초 재생한다.
2. `liveNodes` 가 **양수**이고 시간에 따라 단조 감소하지 않는지 본다.
   (기준값: 37루프 뒤 약 +400, `retireQ` 약 500)

### R4 · 유휴 프리워밍이 첫 클릭 전 콘솔 경고를 4개 → 101개로 늘린다 — **[거슬림]** — ✅ **시험 중 고쳐짐**

> **상태**: 성능 담당이 프리워밍을 `requestIdleCallback` 에서 **첫 사용자
> 제스처**(`document` 캡처 단계의 `pointerdown`/`keydown`, 1회만)로 옮겼습니다.
> 제스처 안에서 짓기 때문에 브라우저가 경고를 내지 않으면서 첫 클릭 지연
> 개선 효과는 유지됩니다 — 제가 §트레이드오프에서 검토했던 네 갈래보다
> **더 나은 다섯 번째 길**입니다(문서화로 넘기려던 것을 실제로 없앴습니다).
>
> **재확인**: 아무 조작 전 경고 **4개**(`booted=false`), Play 클릭 뒤에도 총 4개,
> `ctxState='running'`·재생 정상. 101 → 4 로 확인됩니다.
> 아래 기록은 «프리워밍을 다시 유휴 콜백으로 되돌리면 안 되는 이유» 로 남깁니다.

`src/main.js` 가 (수정 전) 사용자 제스처 없이 `boot()` 를 불렀습니다.

```js
const prewarm = () => { try{ boot(); }catch(e){ /* 제스처 필요 */ } };
if(typeof requestIdleCallback === 'function') requestIdleCallback(prewarm, {timeout:2500});
else setTimeout(prewarm, 700);
```

`boot()` 는 그래프 전체를 짓습니다. 정지(suspended) 상태의
AudioContext 에서 노드를 만들 때마다 크롬이 경고를 하나씩 냅니다.

**A/B 로 확인했습니다** (같은 빌드, 클릭 전 5초):

| | 첫 클릭 전 경고 총계 |
|---|---|
| 프리워밍 그대로 | **101** (`AudioContext was not allowed to start` 96 + `AudioContext is "suspended"` 4 + ScriptProcessorNode 1) |
| `requestIdleCallback` 을 지운 대조군 | **4** |

기능에는 영향이 없습니다 — `booted=true` 로 잘 지어지고, 클릭하면
`ctx.state='running'` 이 되며 재생됩니다. 프리워밍의 목적(첫 클릭 지연 단축)도
달성됩니다. 순수하게 **콘솔이 시끄러워지는** 문제입니다.

다만 시끄러움에는 값이 있습니다 — 이 로그 홍수 속에서는 진짜 오류가 안 보입니다.
그리고 앱을 처음 보는 사람에게 «뭔가 잘못됐다» 는 인상을 줍니다.

#### 재현 절차

1. 개발자도구 콘솔을 연다 (필터 없음).
2. <https://slow0704-eng.github.io/pulse16/> 를 연다.
3. **아무것도 클릭하지 않고** 5초 기다린다.

**관측**: 노란 경고 약 100줄.

- **그대로 둔다**: 비용 0. 콘솔은 계속 시끄럽다.
- **프리워밍을 뺀다**: 경고는 사라지나 첫 클릭 지연이 도로 늘어난다 —

**실제로 채택된 해법 (더 나음)**: 프리워밍을 **첫 제스처**로 옮기면

```js
if(o.gtrOct !=null) gtrOct =o.gtrOct;                             // 방어됨
```

바로 아래 두 줄은 `!=null` 로 막아 두고 위 세 줄만 안 막았습니다.
`rootNote` 가 없는 저장본을 넣으면 `rootNote === undefined` 가 됩니다.

**재현**: R1 절차의 JSON 에서 `rootNote` 키만 뺀다 → 새로고침 → 콘솔에
`rootNote` 입력 → `undefined`.

시험에서는 예외까지 가지 않았지만(드럼만 있는 패턴이라 음정 계산을 안 탐),
음정 트랙이 있는 저장본이면 음높이가 `NaN` 이 되는 길입니다.

**트레이드오프**: 세 줄에 같은 `!=null` 가드를 붙이는 것뿐이라 비용이 사실상
0 입니다. 오히려 **지금처럼 바로 옆 두 줄과 다르게 생긴 것이 더 위험합니다** —
읽는 사람이 «여기는 일부러 안 막았나?» 를 매번 판단해야 합니다.

**구현 명세**: `src/ui/edit.js:114` 를 아래 두 줄과 같은 모양으로 통일한다.
```js
if(o.rootNote  != null) rootNote  = o.rootNote;
if(o.scaleName != null) scaleName = o.scaleName;
if(o.baseOct   != null) baseOct   = o.baseOct;
```

## 3. 통과 항목 중 특별히 잘 되어 있는 것

기록해 둘 값어치가 있어 남깁니다 — **여기에 방어 코드를 더 넣지 마십시오.**

- **`HAS_TONE` 폴백이 진짜로 돕니다.** 지시받은 옛 `link()` TypeError 회귀는
  재현되지 않았고, 폴백에서 실제로 −4.2 dBFS 의 소리가 납니다.
  `src/core/util.js:34` 의 `(a.output||a).connect(b.input||b)` 가 제 몫을 합니다.
- **샘플 CDN 실패 경로 5개가 전부 다릅니다.** 킷·샘플러·루프·직접URL·전체받기가
  각각 알맞은 한국어 메시지를 내고 전부 합성으로 되돌아갑니다.
  특히 `preloadAll()` 이 실패 6건에서 **스스로 중단**하는 것(6초에 끝남)은
  잘 만든 부분입니다 — 안 그랬으면 70여 개 요청을 다 기다렸을 겁니다.
- **`loadState()` 의 try/catch 두 겹**(JSON 파싱 따로, 적용 따로)이
  손상 저장본 대부분을 공장 초기화로 되돌립니다.
- **`fillTracks()` 의 발상이 옳습니다.** perc 트랙이 늘었을 때를 대비한
  그 설계 덕분에 옛 저장본 4종이 전부 통과했습니다. R1 은 이 발상이
  **부족해서**가 아니라 **`bass` 까지 안 넓혀서** 난 문제입니다.
- **300회 연타에 예외 0건.** 실행취소 스택 상한(60)도 제대로 돕니다.

## 6. 배포본 vs 로컬

지시받은 «밑줄 파일이 Jekyll 에 먹히는» 문제는 **재현되지 않았습니다.**
`.nojekyll` 이 커밋돼 있고 `_raw.js`·`_build.js` 둘 다 200 입니다.

배포본에서만 나는 문제를 따로 찾아 봤습니다.

| 검사 | 결과 |
|------|------|
| HTML 이 참조하는 자산 49개 전부 200 | **통과** |
| 밑줄 파일(`_raw.js`, `_build.js`) | **통과** — 둘 다 200, `.nojekyll` 이 git 에 있음 |
| **대소문자 불일치** (Pages 는 구분, 윈도우 로컬은 안 구분 — 전형적인 «배포본만 죽는» 함정) | **통과** — 참조 49개 전부 실제 파일명과 정확히 일치 |
| HTML 이 참조하지 않는 `src/`·`styles/` 파일 (죽은 파일) | **통과** — 0개 |
| 혼합 콘텐츠(`http://`) | **통과** — 0건 |
| 루트 진입점 `/pulse16/` → `pulse16-mk16.html` | **통과** — meta refresh + `location.replace` 둘 다 동작 |
| 모듈 로드 상태 (arrange · harmony · groove) | **통과** — 배포본에서 세 줄(곡구조·화성·그루브) 모두 표시됨 |
| 배포본 ↔ 로컬 내용 동일성 | **통과** — 49개 중 32개 완전 동일. 나머지 17개 차이는 **CRLF→LF 뿐** (차이 바이트 수 = 그 파일의 줄 수와 정확히 일치. 예: `fills.js` 179줄·179바이트, `01-rock.js` 507줄·507바이트) |
| 콘솔 (배포본) | 로컬과 **동일** |

### 6.1 그러나 — 실제로 «배포본만 뒤처진» 상태를 목격했습니다

시험 시작 시점(커밋 `c221eef`)에 **로컬 HTML 이 `src/audio/modal.js`,

## 7. 시험 방법 · 재현 가능성

- 도구: Python Playwright + Chromium (`chromium-1234`).
  공용 MCP 브라우저는 다른 팀이 동시에 탭을 열고 닫아 `evaluate` 가
  엉뚱한 탭에 붙는 일이 있어, **전용 브라우저를 따로 띄워** 측정했습니다.
- 로컬 서버: 프로젝트 폴더를 읽기 전용으로 서빙하는 스크립트를
  임시 폴더에 두고 사용했습니다. Tone.js 없는 판(`/notone.html`)은
  프로젝트 파일을 건드리지 않고 **응답을 메모리에서 바꿔** 만들었습니다
  (cdnjs `<script>` 의 URL 만 죽은 주소로 치환).
- 네트워크 실패는 Playwright 의 `route(...).abort()` 로,
  localStorage 차단은 `add_init_script` 로 `window.localStorage` getter 를
  throw 하게 만들어 모사했습니다.
- 시험 스크립트 전량은 세션 임시 폴더에 있으며 프로젝트에는 남기지 않았습니다.

**정직 고지**
- 백그라운드 탭(R2)은 **실제 탭 전환으로는 재현하지 못했습니다.**
  Playwright 가 headless·headed·CDP 어느 쪽으로도 `document.hidden` 을
  `true` 로 만들지 못했습니다. 크롬의 «숨은 탭 타이머 1초 클램프» 를
  모사한 결과이며, **실제 브라우저에서의 확인이 남아 있습니다.**
- localStorage 차단은 **사파리 프라이빗 모드 자체가 아니라** 그 동작을
  모사한 것입니다.
- 3분 누수 시험은 Chromium 헤드리스 기준입니다. 이 환경에서 오디오
  컨텍스트 시계가 벽시계보다 느리게 가는 구간이 관측됐으므로
  (10초 대기에 ctx 6.3초), **타이밍 절대값은 신뢰하지 마십시오.**
  누수 판정에 쓴 것은 절대 시간이 아니라 «루프 수 대비 추세» 입니다.
