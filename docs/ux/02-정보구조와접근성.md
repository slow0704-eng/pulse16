## 0. 한 줄 결론

이 화면은 **복잡하지 않고 밀도가 높다** — 그건 전문가용 도구로서 옳은 선택이다.
무너지는 지점은 밀도가 아니라 세 곳이다.

1. **켜짐/꺼짐이 안 보인다.** 변주 토글 7개는 ON 일 때와 OFF 일 때 계산된 스타일이 **완전히 동일**하다. 2글자 한글만 바뀐다.
2. **키보드로는 못 쓴다.** Play 버튼에 닿으려면 **Tab 387번**이다. 프리셋 칩 357개가 DOM 앞에 있고 건너뛸 방법이 없다.
3. **좁은 화면에서 악기가 사라진다.** 390px 에서 스텝 격자의 **603px / 948px (64%)** 가 잘린다. 스타일시트 전체에 레이아웃용 미디어 쿼리가 **1개**(max-width:560px, 태그라인 숨김)뿐이다.

반대로 잘 되어 있는 것도 분명히 있다. 먼저 적는다(§1.0).

### 1.1 1920 × 1080

```
|<-------- 1920 --------------------------------------->|
|   450px 빈 여백   |<---- 1020 ---->|   450px 빈 여백   |
```

- `.unit` 실측 폭 **1020px** (`layout.css:6 max-width:1020px`). 뷰포트의 **53%** 만 쓰고 양옆 **각 450px** 가 빈다.
- 그 좁은 1020px 안에서 프리셋 칩 라이브러리는 **높이 220px 창**에 갇혀 있다. `#chips` `clientHeight 220 / scrollHeight 1434` → **1214px(85%)가 스크롤 밖**. 화면에는 위아래로 남는 공간이 널려 있는데 정보는 우표만 한 창으로 본다. **가로도 세로도 동시에 낭비**하는 드문 경우.
- 문서 전체 높이 **2495~2623px** (로드마다 변주 바 행 수가 달라 변동). 1080 뷰포트로 **2.4화면**.
- 트랜스포트가 줄바꿈되어 **HELP 버튼 하나가 두 번째 줄을 독차지**한다. 트랜스포트 실측 높이 **150px**.
- 변주 바 실측 높이 **241px**, 행 7개(로드에 따라 4개). 토글 7개가 전부 「꺼짐」이고 **전부 똑같이 생겼다**.
- **Keys 2 / Guitar 2 는 머리(strip)만 있고 격자가 없다.** `.roll.k2 .note` = **0개**, `.roll.g2 .note` = **0개** (`.roll.k` 는 128개). 화면상 「만들다 만 트랙」으로 읽힌다.
- 각 롤 헤드 왼쪽 300px 열의 아래쪽이 **비어 있다** — 롤 4개 × 약 100px = 죽은 공간 400px.

### 1.2 1440 × 900

- 레이아웃이 **1920과 동일**. `.unit` = 1020px, `.scroller` 가로 잘림 **0px**, 클리핑 요소 **0개**.
- 즉 실제 브레이크포인트는 대략 1048px 아래에서 처음 발생한다. 1440과 1920은 별개 케이스가 아니다.
- 문서 높이 2563px.

### 1.3 1024 × 768

- `.unit` = **981px** (body padding 14px×2 때문에 1020 미만으로 축소). `.scroller` 가로 잘림 **0px** — 격자는 아직 다 보인다.
- **첫 스텝 패드의 문서 좌표 y = 1170px.** Play 버튼은 y = 628px.
  → **768 높이 뷰포트에서 Play 와 드럼 격자 7행을 동시에 볼 수 없다.** 드럼 격자는 y 1170~1470 이므로 Play(628)와 최소 542px 떨어져 있다. 「누르고 → 결과를 본다」 사이에 스크롤이 낀다.
- 첫 화면(스크롤 0)에 보이는 것: 헤더 · 프리셋 라이브러리 · 샘플 뱅크 · 트랜스포트. **악기는 한 칸도 안 보인다.**
- 칩 창의 **스크롤바가 눈에 보이기 시작**하고 맨 아래 줄이 **행 중간에서 잘린다**. 「더 있다」는 유일한 단서가 이 잘린 반 줄이다.
- 이 로드에서는 Tone.js CDN 이 실패했다(`#stat` = "내장 스케줄러로 실행", `#kstat` = "Tone.js 없음 — 샘플 기능 사용 불가"). 실패 메시지가 뱅크 바 한가운데 붉은 11px 텍스트로 뜨는데 **aria-live 가 없어 스크린리더에는 전혀 전달되지 않고**, 시각적으로도 다른 상태 문구와 같은 크기다. `#preload`·`#cload` 는 조용히 disabled 로 바뀌는데 Play 는 그대로 활성이라 「무엇을 못 하게 됐는지」는 붉은 한 줄이 전부다.

### 1.4 768 × 1024

- `.unit` = **725px**. **여기서 격자가 처음 잘린다**: `.scroller` `scrollWidth 948 / clientWidth 723` → **225px 숨음**. 눈으로 확인: 룰러가 1·2·3 까지만 보이고 **4박(스텝 13~16)이 오른쪽 밖**.
- 잘림 자체는 `.scroller{overflow-x:auto}` 로 의도된 것이라 페이지 가로 스크롤은 없다(`documentElement.scrollWidth 753 < 768`). 문제는 **그 다음**이다.
- **트랙 이름 열이 같이 사라진다.** `.row .strip` 의 `position` 은 **static** — 스텝 13을 보려고 오른쪽으로 밀면 Kick/Snare/Clap/Hat… 라벨과 음소거 점과 볼륨이 전부 화면 밖으로 나간다. 7행짜리 격자에서 **어느 줄이 무슨 악기인지 알 수 없는 상태로 편집**하게 된다.
- **박자 안내선도 없다.** 룰러는 격자 맨 위에만 있고, 그 아래 300~600px 에 있는 베이스·기타 롤에는 마디 구분이 **전혀** 없다(§2 P2-16).
- 재생 중 스크린샷이 잡혔다: STOP 버튼은 주황으로 확실히 변한다(`.play[data-on="1"]` 규칙 있음). 반면 같은 화면의 **Kit 셔플은 「켜짐」인데 회색 그대로** — 같은 페이지 안에서 토글 표현이 일관되지 않다는 것이 한 장에 같이 찍혔다.
- 트랜스포트 150px, 변주 바 241px. 룰러 오버플로 실측: `.rack`·`#ruler`·`.playfield`·`#drums`·`.row` 모두 우측으로 **204px** 초과.

### P0-1. 변주 토글 7개의 ON 상태가 시각적으로 존재하지 않는다

**근거 — 실측 스타일 비교.** `#shuf` 를 눌러 ON 으로 만든 뒤 OFF 인 `#fill` 과 계산된 스타일을 비교했다.

```
#shuf  data-on="1"  text="켜짐"
#fill  data-on="0"  text="꺼짐"

backgroundImage : linear-gradient(rgb(59,66,76), rgb(44,50,58))   ← 동일
backgroundColor : rgba(0,0,0,0)                                    ← 동일
color           : rgb(139,144,153)                                 ← 동일
borderColor     : rgb(23,26,31)                                    ← 동일
boxShadow       : none                                             ← 동일
fontWeight      : 400                                              ← 동일

다른 속성: 0개
```

원인은 한 줄이다. `styles/` 전체에 **`.util[data-on="1"]` 규칙이 없다.**
`grep -rn "util\[data-on" styles/` → 결과 없음. 반면 `.slot`·`.play`·`.chip`·`.cat`·`.sub`·`.lbtn`·`.pbtn` 은 모두 `[data-on="1"]` 규칙이 있다. `.util` 만 빠졌다. `controls.css:89` 에서 `.slot,.util{...}` 로 기본형은 공유하는데 ON 규칙은 `.slot` 에만 붙었다(`controls.css:93`).

해당 버튼: `#shuf` `#pshuf` `#fill` `#mel` `#form` `#prg` `#grv` — **변주 기능 전부.**

**결과**: 「무엇이 켜져 있나」를 12px `text-transform:uppercase` 한글 2글자로만 알 수 있다. 그 글자 색은 배포본에서 `--panel(#2b3038)` 위 **4.14:1** 로 WCAG 1.4.3 미달이기도 하다. 게다가 요약해 줄 `#varstat` 은 **빈 문자열**이다(실측).

또한 `aria-pressed` 가 없어 접근성 이름이 그냥 **"꺼짐"** 이다 — **무엇이** 꺼졌는지 스크린리더는 알 수 없다(라벨 「Kit 셔플」은 형제 `<span class="lbl">` 이고 연결되어 있지 않다). WCAG **4.1.2**.

**WCAG**: 1.4.1(색/텍스트만 의존 — 여기선 텍스트만) · 1.4.3 · 4.1.2
**영향**: 전원. 변주는 이 도구의 핵심 판매 포인트다.

### P0-2. 키보드로 Play 에 닿으려면 Tab 387번

**근거 — 실측 탭 순서 인덱스** (보이는 포커서블만 집계):

```
전체 탭 스톱          967
Play 버튼             387번째   ← 앞에 프리셋 칩 357개
선율 토글             409번째
첫 스텝 패드          424번째
베이스 음소거         566번째
마지막 기타 노트      961번째
```

- 격자 셀만 **496개**(`.pad` 112 + `.note` 384)가 각각 `tabindex="0"` 이다.
- **스킵 링크가 없다.** 랜드마크는 `<main>` **하나**, 제목은 `<h1>` 하나 + 도움말 다이얼로그의 `<h2>` 하나. 스크린리더에서 「제목으로 이동」해도 갈 곳이 없다.
- 격자 셀은 전부 납작한 `role="button"` 이다. `role="grid"/"row"/"gridcell"` 이 아니라서 **행·열 개념이 없다** — 방향키 이동도 없다(`build.js:146` 은 Space/Enter 만). Perc 트랙 16번 칸에 가려면 Tab 을 112번 눌러야 한다.

**WCAG**: **2.4.1 Bypass Blocks (Level A)** — 반복 블록을 건너뛸 수단이 없다. + 2.4.3 · 4.1.2
**영향**: 키보드 전용 사용자, 스크린리더 사용자, 스위치/음성 제어 사용자. **사실상 사용 불가.**

### P0-3. 390px 에서 스텝 격자를 쓸 수 없다

`--strip:300px` 이 고정이고 `--cell:34px` 도 고정이다. 스타일시트 전체 미디어 쿼리는 **2개**뿐이다.

```
layout.css   @media (prefers-reduced-motion:reduce)
layout.css   @media (max-width:560px)      ← .tagline/.stat 숨김, .brand 27px
rack.css     없음
sequencer.css 없음
controls.css 없음
```

즉 **격자·롤·변주 바·Loop Deck 에 대한 반응형 처리가 하나도 없다.** 390px 에서:

```

**지금 들리는 것 (NVDA/VoiceOver 기준, 구조상 추정 — 실기기 테스트는 안 했다)**

**좋은 점**: 라벨이 「Kick 1박 3번째 스텝」이라 **위치를 말로 알려 준다.** 격자 UI 에서 이걸 안 해 놓은 제품이 훨씬 많다. 유지할 것.

2. **방향키가 없다.** `build.js:146` 은 Space/Enter 만 본다. 격자 위젯의 관례(방향키 이동 + 로빙 tabindex)가 없다. Perc 16칸 = Tab 112회.
3. **벨로시티 3단이 2단으로 뭉개진다.** 값은 0/1/2(꺼짐/약하게/강세)인데 노출은 `aria-pressed` 불리언이다(`build.js:128`, `meters.js` 갱신부). **"눌림"만 들리고 약한 타격과 강세를 구분할 수 없다.** 화면은 형태 단서까지 넣어 3단을 구분해 놨는데(§1.0) 그 정보가 접근성 트리에서 사라진다.
4. **음소거 상태를 알 수 없다.** `#bmute` 등 12개 모두 `role="button"` + `aria-label="Kick 음소거"` 인데 **`aria-pressed` 가 없다**. 「Kick 음소거, 버튼」만 들린다 — 지금 음소거인지 아닌지가 없다. 시각적으로는 `.mute[data-off="1"]` 이 배경을 `#3c424b` 회색으로 바꾸지만(색/밝기 단독, 대비 **3.75:1**, 크기 **9×9px**), 그 정보가 이름에 없다. **WCAG 4.1.2.**
5. **재생 위치가 안 들린다.** `#head` 는 `pointer-events:none` 인 장식 div 이고 ARIA 가 없다. 현재 스텝·현재 마디를 알 방법이 전무하다. (매 스텝 announce 는 88BPM 에서 초당 6회로 명백히 과하다 — §3 에서 마디 단위 대안을 제시한다.)

**WCAG**: 1.3.1 · 4.1.2 · (2.4.3)
**영향**: 스크린리더 사용자, 키보드 전용 사용자.

### P2-15. 화성 진행 행이 반쯤 비어 있다

`#prgmode` 가 **옵션 0개 + `hidden`** 으로 렌더된다(실측). `events.js:410` 이 `typeof progMode==='undefined'` 라서 의도적으로 숨긴 것이고 코드 주석에 이유가 있다. 하지만 화면에는 「화성 진행 — 코드가 마디마다 바뀝니다」 라벨 옆에 **버튼 하나만** 덩그러니 남아, 다른 6개 행과 형태가 달라 「고장난 줄」로 보인다.

### P2-16. 변주 바 행 개수가 로드마다 4~7개로 달라진다

`formrow`/`prgrow`/`grvrow` 는 `events.js:380,402,426` 에서 데이터 모듈 존재 여부에 따라 `hidden=false` 로 풀린다. 실측: 1920 두 번째 로드에서 **7행**, 1024·768·390 로드에서 **4행**. 같은 사이트에서 같은 컨트롤이 있다가 없다. 근육 기억이 형성되지 않고, 첫 화면 이후 **레이아웃이 165px 밀린다**(241 vs 이후 확장).

## 3. 개선안

### 3.1 초보자와 숙련자에게 무엇이 앞에 와야 하나 — 답부터

**두 사용자의 첫 동작이 다르다.**

- 초보자: 「소리를 듣고 싶다」 → **Play** 와 **프리셋 하나**
- 숙련자: 「어제 만든 것을 이어서」 → **패턴 뱅크**, **격자**, **변주**

지금은 둘 다 틀렸다. 첫 화면에 오는 것은 **프리셋 칩 357개**다. 초보자에겐 압도이고(357개 중 무엇?), 숙련자에겐 매일 스크롤해서 지나치는 벽이다. 그리고 **Play 는 y=628, 격자는 y=1170** — 둘의 목적지가 둘 다 접혀 있다.

**결론: 순서를 바꾼다. 라이브러리를 트랜스포트 아래로 내리고, 트랜스포트를 sticky 로 만든다.**

```
현재                                     개선
─────────────────────────────           ─────────────────────────────
헤더                                     헤더 + 지금 상태 요약 ← 신규
라이브러리 (칩 357개, 335px)  ← 벽      ┌ sticky ────────────────┐
샘플 뱅크 (3줄)                          │ Play  Tempo Swing Master │
트랜스포트  y=628                        │ 뱅크 ABCD   변주 요약칩  │ ← 항상 보임
변주 바 (241px, 7행)                     └─────────────────────────┘
패널 바                                  ★ 스텝 격자  ← 첫 화면
★ 스텝 격자  y=1170  ← 접힘              베이스 / 건반 / 기타 롤
롤들                                     ▸ 패턴 라이브러리 (접힘, 검색)
                                         ▸ 변주 (접힘, 요약칩이 상태 표시)

```

**점진적 공개가 필요한 곳 — 우선순위대로**

| 위치 | 지금 | 제안 | 왜 |
|---|---|---|---|
| **샘플 뱅크 3줄**(Kit·Loop Deck·직접 URL) | 항상 펼침 | **접기.** 특히 「직접 URL」은 개발자/탐험가용 | 세션당 0~1회 사용. 상시 노출 가치 최저 |
| **변주 세부 select 12개** | 항상 펼침 | 토글 7개 + **요약 칩**만 상시, select 는 토글 ON 시 노출 | 켜지 않은 기능의 주기·종류는 볼 필요가 없다 |

### 3.4 격자 접근성 — grid 역할 + 방향키 (P1-8, P0-2)

```

**탭 스톱 967 → 약 60.** 격자 4개(드럼·베이스·건반·기타)가 각 1스톱이 되고 칩 목록도 1스톱이 된다.

음소거는 `aria-pressed` 를 붙이고 **텍스트도 준다**: 9px 점 옆에 `M` 글자 또는 취소선. 색/밝기 단독(3.75:1, 9px) 탈출.

재생 위치는 `aria-live="polite"` 로 **마디 단위만** 알린다 — 「2마디」. 스텝 단위는 88BPM 에서 초당 6회로 스크린리더를 마비시킨다.

스킵 링크: `<main>` 첫 자식에 「격자로 바로 가기」 · 랜드마크 5개(`<section aria-label>`) · `<h2>` 5개.

## 4. 트레이드오프 — 항목별 결론

숨기면 초보자에겐 쉬워지고 숙련자에겐 클릭이 는다. 각 항목에서 **어느 쪽을 택했는지** 밝힌다.

### 4.1 라이브러리를 접는다 → **접는다**

- 잃는 것: 숙련자가 프리셋 교체마다 클릭 1회 추가.
- 얻는 것: 첫 화면에서 **335px 확보** → 1024×768 에서 격자가 첫 화면에 들어온다.
- **결론: 접는다.** 근거는 빈도다. 프리셋 선택은 곡 시작에 1~2회, 격자 편집은 수백 회. 게다가 지금 라이브러리는 「펼쳐져 있어도」 15%만 보인다 — 상시 노출의 대가로 얻는 게 별로 없다. **완화**: 닫힌 헤더에 「지금: Boom Bap」을 표시하고 최근 5개를 칩으로 남긴다 → 숙련자의 실제 반복 동작(최근 것 사이 왕복)은 오히려 **빨라진다**.

### 4.2 꺼진 변주의 select 를 숨긴다 → **숨긴다**

- 잃는 것: 「켜기 전에 주기를 4루프로 맞춰 두는」 순서가 막힌다(토글 → select 2단계).
- 얻는 것: 변주 바 **241 → 약 110px**. 「무엇이 켜져 있나」가 즉시 읽힌다.
- **결론: 숨긴다.** 단 **끄더라도 값은 유지**하고(이미 `edit.js` 가 모드를 저장/복원한다), 토글 옆에 현재 값을 작게 병기한다: `[● 켜짐] 4루프·장르맞춤`. 이렇게 하면 「보기」는 유지되고 「조작」만 한 단계 들어간다 — 숙련자가 잃는 것은 실제로 없다.

### 4.3 격자에 방향키 + 로빙 tabindex → **한다**

- 잃는 것: **Tab 만으로 한 칸씩** 가던 사람이 격자 안에서 방향키를 배워야 한다.
- 얻는 것: 탭 스톱 **967 → 약 60**. 스크린리더가 7×16 표로 인식.
- **결론: 한다.** 「Tab 을 424번 눌러 첫 패드에 간다」는 것은 지원이 아니라 명목이다. 방향키 격자는 ARIA APG 표준 패턴이고 DAW·스프레드시트 관례와 같아서 학습 비용이 사실상 없다. 이 트레이드오프는 대칭이 아니다 — 잃는 쪽이 거의 0 이다.

### 4.4 모바일에서 4칸 페이지 → **한다**

- 잃는 것: 16칸 전체를 한눈에 보는 것. 스텝 3과 스텝 14의 관계 파악이 어려워진다.
- 얻는 것: **터치로 조작 가능해진다**(현재 불가). 셀 34 → 44px.
- **결론: 한다.** 「한눈에 안 보인다」와 「아예 못 만진다」는 비교 대상이 아니다. **완화**: 페이지 탭 위에 16칸 축소 미니맵(칸당 8px = 128px)을 얹어 전체 형태는 항상 보이게 한다 — 개요는 미니맵, 편집은 확대된 4칸.

### 4.5 미터를 sticky 로 올린다 → **올린다 (미니 1개만)**

- 잃는 것: sticky 바가 세로 **약 60px** 를 상시 점유.
- 얻는 것: 클리핑이 조용히 지나가지 않는다.
- **결론: 올린다. 단 출력 1개만.** G.R.·Bass 는 Master 패널에 남긴다. 「기본 상태에서 클리핑을 못 본다」는 오디오 도구로서 결함이지, 취향 문제가 아니다.

### 4.6 넓은 화면 2열 → **한다 (1440 이상만)**

- 잃는 것: 두 레이아웃 유지 비용. 1020 고정의 「완결된 기계」 같은 인상이 옅어진다.
- 얻는 것: 칩 355개가 **220px 창을 탈출**한다. 낭비 900px 회수.
- **결론: 1440 이상에서만 2열.** 1024~1439 는 지금의 1열 유지. 브레이크포인트 1개 추가로 끝난다. 1020 고정의 미학은 **의도된 것으로 존중하되, 1440 이상에서 47% 를 버리는 것은 미학이 아니라 미완성**이다.

### 4.7 2번 트랙에 격자 vs 램프 → **램프 (§3.9)**

- 격자: 정직하고 편집 가능. **+500px**, 화면 부담 큼.
- 램프: **+40px**, 「울린다」는 확인. 편집 불가.
- **결론: 램프.** 설계상 자동 배정 트랙이므로 편집 UI 는 지키지 못할 약속이다.

### 4.8 `#stat` 을 모바일에서 되살린다 → **되살린다**

- 잃는 것: 좁은 헤더에 10px 텍스트 한 줄.
- 얻는 것: 「Tone.js 없음」 같은 결정적 메시지가 모바일에서 전달된다.
- **결론: 되살린다.** 헤더에서 빼고 sticky 바 아래 한 줄 토스트로 옮긴다. `.tagline`("Verified Presets")은 계속 숨겨도 된다 — **그건 진짜 장식이고 `#stat` 은 아니다.**

## 부록 B. 검사한 것 / 검사하지 않은 것

**검사함**: 폭 1920·1440·1024·768·390 의 전체 페이지 스크린샷과 DOM 실측 · axe-core(로컬, 1280×900 및 390×844, 둘 다 위반 없음) · 대비 22쌍 계산 · 포인터 타깃 전수 · 탭 순서 인덱스 · 배포본 CSS 를 `fetch` 해 로컬과 비교 · 변주 토글 ON/OFF 계산 스타일 비교 · `keys2`/`gtr2` 의 오디오/시각 구현 대조 · 스텝 패드·노트·음소거의 ARIA 속성.
