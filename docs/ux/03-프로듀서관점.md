# 03 — 프로듀서 관점: 이걸로 곡이 나오는가

작성자: 현업 프로듀서 관점 리뷰 (Ableton·FL 상주, 데모는 Suno 로 뽑는 워크플로)
대상: 배포본 <https://slow0704-eng.github.io/pulse16/> · 커밋 `c221eef`
방법: Playwright 로 조작 + 오프라인 렌더 → ffmpeg EBU R128 · 1초 창 RMS

---

## 0. 정직 고지 — 무엇을 했고 무엇을 안 했는가

**소리는 듣지 못했습니다.** 그래서 «좋다/나쁘다» 는 쓰지 않고, 잰 수치와 패턴
데이터만 근거로 씁니다. 리듬 골격의 «장르답다» 판정은 청감이 아니라
**16스텝 패턴 문자열을 직접 떠서** 판단했습니다.

측정 경로 두 개를 썼습니다.

- `mcp__pulse-audit__audio_measure` — 이 도구는 **칩만 누르고 Play** 한 상태를 녹음합니다
  (`mcp/pulse-audit/server.js` 의 `recordApp`). 즉 «부팅 기본값» 의 측정치입니다.
- 필인·선율·셔플·곡구조를 **켠** 상태는 위 도구로 잴 수 없어, 같은 `capture.js`
  워클릿을 재사용하는 임시 캡처 스크립트를 스크래치패드에 따로 두고 돌렸습니다.
  `src/` · `tools/` 는 한 줄도 건드리지 않았습니다.

**⚠ 먼저 알아야 할 것 — 배포본과 작업 트리가 다릅니다.**
배포본이 실제로 로드하는 스크립트 목록에 `src/seq/arrange.js`(곡 구조),
`src/data/harmony.js`(화성 진행), `src/audio/modal.js` 가 **없습니다.**
확인: `git show c221eef:pulse16-mk16.html | grep -c "arrange.js\|harmony.js"` → `0`.
그래서 배포본에는 «곡 구조 / 화성 진행 / 그루브» 행이 화면에 아예 존재하지 않습니다.
작업 트리(`pulse16-mk16.html:171~184`)에는 그 세 행이 이미 들어 있습니다.
**아래 판정은 배포본 기준입니다.** 미배포 기능은 그렇게 표시하고 따로 쟀습니다.

평가하지 않은 것(써 보지 않았으므로): Loop Deck 배경 루프, «전체 받기» 샘플
로딩과 직접 URL, keys2·gtr2 2번 트랙, 접근성, 모바일 레이아웃.

## 1. 시나리오별 실행 기록

### 시나리오 A — «록 트랙 하나를 30초 분량으로 만들어 내보낸다»

누른 순서: `Rock` 카테고리 → `Rock` 칩 → (프리셋이 BPM 130 · Swing 0 · Root A ·
Minor Pentatonic 을 한 번에 잡음) → `Play`.

여기까지 **클릭 두 번**에 록 루프가 돕니다. 이건 진짜로 빠릅니다.
그리고 그 다음부터 막힙니다.

| 상태 | 길이 | 적분 LUFS | **LRA** | 트루피크 | 1초창 RMS 폭 |
|---|---|---|---|---|---|
| 칩 + Play 만 (부팅 기본값) | 28.3초 | −11.9 | **0.4 LU** | −2.2 dBFS | — |
| 셔플·패턴셔플·필인·선율 4개 켬 | 29.6초 | −12.2 | **3.2 LU** | −2.8 dBFS | 5.1 dB |
| + 곡 구조 켬 (**미배포**, 작업 트리) | 69.4초 | −12.9 | **5.4 LU** | −2.2 dBFS | 5.6 dB |

**LRA 0.4 LU** 가 이 문서에서 가장 중요한 숫자입니다. 30초 동안 라우드니스가
0.4 LU 밖에 안 움직였다는 뜻이고, 그건 «음악이 아무 데도 가지 않았다» 는 것의
계량 표현입니다. 상용 록 싱글은 보통 4~8 LU 입니다. 인트로도 전개도 후렴도
마무리도 없고, 같은 1마디가 28초 동안 그대로 돌았습니다.

토글 4개를 켜면 3.2 LU 로 올라갑니다. 다만 1초창 RMS 시계열을 보면
`−13 −14 −13 −14 −14 −12 −11 −11 −11 −12 −15 −11 −11 −12 −14 −15 −15 −16 −15`
— 오르내리기는 하는데 **방향이 없습니다.** 무작위 걸음이지 «쌓았다가 터뜨린»
모양이 아닙니다. 셔플은 «다음 마디에 뭐가 올지 모르는 상태» 를 만들 뿐,
«지금이 후렴» 이라는 상태를 만들지 않습니다.

미배포 곡 구조를 켠 세 번째 줄이 답을 보여 줍니다. RMS 시계열이
`−15 −16 −15 −16 −15 … (45초까지 평탄) … −13 −12.5 −12.1 −11.7 −12.7 −12.4`
로, 45초 지점부터 **한 방향으로 3~4 dB 올라갑니다.** LRA 5.4 LU — 상용 범위에
들어옵니다. 즉 **문제의 답은 이미 저장소 안에 있고, 배포만 안 된 상태입니다.**

**여기서 포기한 지점**: 30초를 만들었는데 **가져나갈 방법이 없습니다.**
DOM 을 뒤져 확인했습니다 — `a[download]` 0개, `exportWav`·`exportMidi`·
`shareUrl` 같은 전역 함수 0개, 화면에 «내보내기/다운로드/공유» 문구 0개.
녹음 버튼도 없습니다. **화면 녹화 말고는 밖으로 나오는 길이 하나도 없습니다.**

부수 발견: 곡 구조를 켜도 «30초 분량» 은 못 만듭니다. `arrange.js` 의 가장 짧은
폼이 48마디이고, 130 BPM 에서 48마디 = **88초**입니다(88 BPM Boom Bap 이면 131초).
30초짜리 데모용 짧은 폼이 없습니다.

### 시나리오 B — «힙합 비트를 만들어 Suno 레퍼런스로 쓴다»

`Hip Hop` → `Boom Bap`. 프리셋이 잡아 준 값: BPM 88 · Swing 38.
패턴을 직접 떠 봤습니다.

```
kick  X--x----X---x---     snare ----X-------X---
chat  x-x-x-x-x-x-x-x-     perc  --x---x---x---x-
bass  0--0----5---3---     keys  C---C-----C---C-   (ep)
```

스네어 2·4, 킥이 «1 + 4번째 16분» 으로 밀리고, 셰이커가 8분 뒷박,
베이스가 0→5→3 으로 움직입니다. **골격은 붐뱁입니다.** Swing 38 도 맞습니다.
칩 한 번에 이 정도가 잡히는 건 실제로 강점입니다.

| 상태 | 길이 | 적분 LUFS | LRA | 트루피크 | 1초창 RMS 폭 |
|---|---|---|---|---|---|
| 칩 + Play | 26.1초 | −12.4 | **0.7 LU** | −1.7 dBFS | 3.1 dB |
| 4토글 켬 | 27.6초 | −14.1 | **2.9 LU** | −1.2 dBFS | 5.9 dB |

4토글 켠 쪽의 RMS 시계열이 나쁜 쪽으로 흥미롭습니다.
`−12.5 −14 −11.7 −17 −11.7 −14 −14 −15.8 −12.6 −13.4 −16.2 −16.8 −14.8 −15.1 −17.5 −14 −14.5 −15.6 −17.6 −14.6 −16.6 −15.9 −16.3 −13.4 −14.2 −14.5 −14.8`
— **평균이 시간이 갈수록 내려갑니다** (앞 8초 평균 약 −13.7, 뒤 8초 약 −15.5).
패턴 셔플이 «지금 칩 필터 안에서 무작위» 로 고르니까, 성긴 프리셋을 뽑을 확률이
누적되면서 트랙이 점점 얇아집니다. 곡이 **꺼져 갑니다.** 후렴으로 가는 게 아니라
반대로 갑니다. 이건 무작위 셔플의 구조적 결과이고 튜닝으로는 못 고칩니다.

**여기서 포기한 지점 두 개.**

1. 오디오도 MIDI 도 안 나옵니다(시나리오 A 와 동일).
2. **Suno 에 넘길 텍스트가 안 나옵니다.** 앱은 이미 다 알고 있습니다 —
   장르명(`Boom Bap`), 계열(`C`), BPM 88, Swing 38, Root A, Minor Pentatonic,
   킥 `deep`, 스네어 `crack`, 베이스 `sub`(808), 건반 `ep`(일렉 피아노),
   퍼커션 `shaker`. Suno 프롬프트에 필요한 건 정확히 이 목록입니다.
   그런데 화면에서 긁어 복사할 수 있는 형태로는 어디에도 없습니다.
   `genres/` 문서에 «뽑아낸 속성» 이 이미 정리돼 있는데도 앱은 그걸 모릅니다.

Suno 파이프라인의 앞단이 되려면 나와야 하는 것은 결국 두 개입니다:
**② 참고용 오디오 파일 하나 + ① 파생 속성 텍스트 한 덩이.** 지금은 0개입니다.

### 시나리오 C — «장르를 모르는 사람이 아무거나 눌러 본다»

칩을 세어 봤습니다: **357개, 그중 301개가 «·» 규칙 파생(청감 미검증).**
그런데 화면 라벨은 «Pattern Library — 208종 · 208종 표시» 입니다.
배포본 HTML 28행에 208 이 하드코딩돼 있고 갱신되지 않습니다
(작업 트리는 `build.js:366` 에서 고쳐졌습니다). 사용자는 «208종» 이라고 읽으면서
바로 아래 «전체 357» 버튼을 봅니다.

무작위로 눌러 봤습니다: Hyperpop(155) · Gqom(127) · Doom(70) · Bossa Nova(130) ·
Frenchcore(205) — BPM 이 다 장르 범위에 맞게 바뀝니다.
그리고 **357개를 전부 눌러 상태를 검사했습니다: 드럼이 텅 빈 프리셋 0개,
LIB 에 없어 로드 실패하는 칩 0개.** 규칙 파생 칩까지 포함해 전부 소리가 납니다.
`Chutney Soca` 를 골라 재 보니 −11.9 LUFS · TP −3.0 dBFS · 크레스트 9.6 dB ·
플랫 팩터 0 — 클리핑도 무음도 없습니다.

**아무거나 눌러도 망가지지 않는다는 것은 이 도구의 진짜 강점입니다.**
Ableton 에서 프리셋 뒤지다 무음 나오는 일을 하루에 몇 번 겪는 사람 기준으로
357개 전부가 즉시 소리 난다는 건 드문 신뢰도입니다.

**여기서 막히는 지점**: 소리는 나는데, **그 다음에 뭘 눌러야 곡이 되는지
화면이 말해 주지 않습니다.** «Kit 셔플 / 패턴 셔플 / 필인 / 선율» 네 행이
전부 기본값 **«꺼짐»** 입니다. 즉 도구의 목표(«틀어 놓으면 곡이 된다»)를
담당하는 장치 전부가 기본으로 꺼져 있고, 처음 온 사람은 «칩 → Play» 로
0.4 LU 짜리 무한 루프만 듣고 나갑니다. 도움말(`?`)에는 단축키와 뱅크 설명만
있고 «곡을 만드는 순서» 가 없습니다.

### 시나리오 D — «마음에 드는 부분만 고정하고 나머지를 굴린다»

프로듀서가 실제로 하는 일이 이것이라 따로 재현했습니다.
Boom Bap 을 불러 킥만 손으로 고치고 → 패턴 셔플 한 번 → 실행취소.

```
프리셋 킥      = 2001000020001000
내가 고친 킥   = 2000002000200200
shufflePattern → Dance-pop
셔플 후 킥     = 2000200020002000
베이스도 바뀜? = true
undoStack 깊이 = 6
undo 후 킥     = 2001000020001000     ← 프리셋 상태
내 편집 복구?  = false
```

**셔플은 전부 바꿉니다. 그리고 실행취소로도 내 편집이 돌아오지 않습니다.**
원인은 `src/seq/sequencer.js:309 shufflePattern()` 이 드럼 7트랙 + 베이스 + 건반 +
기타를 전부 덮어쓰면서 `pushUndo()` 를 부르지 않기 때문입니다(자동 저장을
지키려는 의도적 설계 — 주석에 그렇게 적혀 있습니다). 그 결과 undo 는 «내 편집
직전» 스냅샷으로 돌아가고, 편집 자체는 복구 불가능하게 사라집니다.

실행취소 범위도 재 봤습니다.

```
reverb 26 → 90,  kick mute false → true,  이후 undo
undo 후 reverb = 90  (되돌아갔나: false)
undo 후 mute   = true (안 돌아옴)
```

`src/ui/edit.js:22 snapshot()` 이 덮는 것은 **뱅크 4개 + src + eng + probT** 뿐입니다.
노브·뮤트·레벨·BPM·Root·Scale 은 실행취소 대상이 아닙니다. 60단계라는 깊이는
넉넉한데, 덮는 면적이 좁습니다.

**트랙 잠금은 존재하지 않습니다.** 이게 Ableton 세션뷰·FL 패턴·Elektron 과
갈리는 가장 큰 지점입니다(§3 비교표).

프리셋별 화성 폭(직접 떠 본 결과, `P.keys` 비트마스크의 근음 degree):

| 프리셋 | 건반 화음 진행 | 서로 다른 화음 수 |
|---|---|---|
| Trap | `0+2+4` 하나 | **1** |
| Pop Punk | 없음(건반 비어 있음, 기타가 0·4) | **0** |
| Rock | `0+2+4` → `1+4+6` | 2 |
| Boom Bap | `0+2+4` → `3+5+7` | 2 |
| House | `0+2+4` → `3+5+7` | 2 |
| Bossa Nova | `0+2+4` → `3+5+7` | 2 |
| Jazz Fusion | `0+2+4` → `2+4+6` | 2 |
| Motown | `0+2+4` → `3+5+7` | 2 |

전부 **한 마디(16스텝) 안에 최대 2코드**, 그 한 마디가 영원히 반복됩니다.
덧붙여 기본 스케일이 Minor Pentatonic 인 프리셋(Rock·Trap·House·Boom Bap)에서는
`pattern-codec.js` 의 `TRIAD(r) = r, r+2, r+4` 가 5음계 위에서 3화음이 아니라
**4도 쌓기(root·4th·b7)** 가 됩니다. 록·힙합에서는 오히려 맞는 선택이지만,
장·단 색이 없다는 뜻이기도 해서 «코드 진행» 이라는 감각은 애초에 안 생깁니다.

### B. 불편하지만 우회 가능

## 3. 이 도구만의 강점 — 개선하다가 잃으면 안 되는 것

### 3-1. 지켜야 할 것 (우선순위대로)

1. **«칩 하나 → 장르 전체» 의 적중률.** 칩 한 번에 BPM·Swing·드럼 7트랙 패턴·
   킷 엔진·튜닝·베이스 설정(엔진/옥타브/게이트/글라이드/블렌드/드라이브/
   크로스오버/톤/서브/엑사이터/덕)·트랙 레벨·Root·Scale 이 **동시에** 잡힙니다.
   Ableton 에서 이걸 하려면 Drum Rack + 각 채널 세팅 + 프로젝트 템포까지
   손으로 맞춰야 합니다. **이 압축률이 이 도구의 정체성입니다.**
2. **357개 전부가 즉시 소리 난다.** 실측으로 확인했습니다(드럼 빈 프리셋 0개,
   로드 실패 0개, 클리핑 0건). 설치 0 · 로그인 0 · 브라우저 하나.
3. **«·» 로 미검증 프리셋을 정직하게 표시한다.** 301/357 이 규칙 파생이라고
   화면에 적어 두는 도구는 흔치 않습니다. 이 정직함은 자산입니다.
4. **측정 문화.** `tools/` 하네스 + `mcp/pulse-audit` 로 «귀로만 판단하지 않는»
   규칙이 코드에 박혀 있습니다. 이 리뷰 자체가 그 인프라 덕에 가능했습니다.
5. **셔플이 자동 저장을 건드리지 않는 배려**(`shufflePattern` 주석). 틀어 놓는
   동안 내 패턴이 덮이지 않습니다 — 방향은 옳습니다. 다만 지금은 «덮이지도
   않지만 되돌릴 수도 없는» 어중간한 상태입니다(§2-A-4).

## 5. 이것 하나만 고치면 쓸 만해진다 — 세 개

### 1위. 오디오 내보내기 (녹음 버튼)

없어서 포기하는 유일한 «절대» 항목입니다. 지금 이 도구는 만든 것을 밖으로
전혀 못 내보내므로, 아무리 좋은 루프가 나와도 세션이 끝나면 사라집니다.
Suno 파이프라인 앞단이라는 목표도 여기서 무조건 실패합니다.

구현이 어렵지도 않습니다 — `mcp/pulse-audit/capture.js` 의 `RECORDER_SRC`
워클릿 + `toWav()` 가 **이미 마스터 출력을 정확히 걷어와 WAV 로 굳히는 일을
하고 있고, 이 리뷰의 모든 측정치가 그것으로 나왔습니다.** 같은 코드를 앱 쪽에서
부르고 Blob 을 `a[download]` 로 떨구면 끝입니다. 오프라인 렌더는 필요 없습니다
(`graph.js` 가 전역 `ctx` 에 묶여 있어 오프라인 전환은 큰 수술입니다 —
실시간 바운스로 가는 것이 옳습니다).

### 2위. 곡 구조를 배포하고 기본으로 켜기 + 짧은 폼 추가

`arrange.js` 가 LRA 0.4 → 5.4 LU 를 만든다는 것을 실측했습니다.
**만들어 놓고 배포를 안 한 상태입니다.** 배포만 해도 목표 ① 이 성립합니다.
그리고 «장르 맞춤» 자동 모드가 있으므로 기본으로 켜도 사용자가 고를 것이 없습니다.
여기에 30~40초짜리 짧은 폼 하나(예: intro 4 + verse 8 + chorus 8 + outro 4 = 24마디)를
더하면 «데모 하나 뽑아 Suno 에 넣기» 가 한 번에 됩니다.

### 3위. 트랙 잠금 + 셔플 전 pushUndo

«마음에 드는 부분을 고정하고 나머지만 굴린다» 는 프로듀서 작업의 기본형이고,
지금은 불가능합니다(§1-D). 트랙 스트립 뮤트 옆에 자물쇠 하나면 됩니다.
동시에 `shufflePattern()` 이 덮기 전에 `pushUndo()` 를 부르게 하면 «셔플했는데
아까가 나았다» 를 되돌릴 수 있습니다. 이 두 줄이 «틀어 놓고 듣는 도구» 를
«같이 만드는 도구» 로 바꿉니다.

> 4위 후보(세 개에 못 넣은 것): 프롬프트 텍스트 복사 버튼. 비용이 가장 싸고
> Suno 파이프라인에 직결되므로, 1위 작업에 곁들일 수 있으면 같이 넣는 편이 좋습니다.
