## 1. 서비스 정의

### 1-1. 한 문장

> **틀어 놓으면 스스로 변주하는 장르 음악 생성기.**
> 사용자가 «만드는» 것이 아니라 «고르고 흘려보내는» 것이 기본 사용 흐름입니다.

### 1-2. 제공 가치

| 가치 | 어떻게 |
|---|---|
| **장르 지식의 코드화** | 357개 프리셋 · 64개 하위분기 · 12계열. «이 장르는 이렇게 친다» 를 데이터로 |
| **끊기지 않는 변주** | 8종 변주 규칙이 루프 주기로 스스로 돎 — 같은 패턴을 두 번 안 들려줌 |
| **설치·계정 없음** | 파일 하나를 열면 끝. 서버·로그인·과금 개념 자체가 없음 |
| **완전 오프라인** | 소리를 전부 실시간 합성. 외부 샘플은 선택 기능일 뿐 |

### 1-3. 이용자와 사용 맥락

| 이용자 | 무엇을 하나 |
|---|---|
| 배경음악으로 트는 사람 | 프리셋 고르고 Variation 켜고 방치 |
| 습작·연습하는 사람 | 장르 패턴을 뜯어 보고 손으로 고침 |
| 음색을 찾는 사람 | 엔진 186종을 트랙별로 갈아 끼움 |

**비즈니스 모델은 정의돼 있지 않습니다** — 과금·계정·사용량 측정 코드가 없습니다.

## 2. 도메인 용어

| 용어 | 뜻 |
|---|---|
| **스텝(Step)** | 1/16박. 한 루프 = 16스텝 = 1마디 |
| **루프(Loop)** | 16스텝 한 바퀴. 모든 변주 주기의 기본 단위 |
| **트랙(Track)** | 소리를 내는 12개 통로 (드럼 7 + 음정 5) |

| **패턴(Pattern)** | 16스텝짜리 연주 데이터 |
| **뱅크(Bank)** | 패턴 한 벌을 담는 독립 슬롯 A~D |
| **프리셋(Preset)** | 패턴+음색+템포+조성+노브값 한 벌 |

| **음도(Degree)** | 스케일 안에서 몇 번째 음인가 (0~7) |
| **변주(Variation)** | 루프가 돌 때 스스로 바뀌는 것들 (8종) |
| **섹션(Section)** | 곡 구조의 한 구간 (인트로·벌스·코러스…) |

## 3. 핵심 도메인 모델

```
계열 (12)
  └ 하위분기 (64)
       ├─ 프리셋 (357)  ── 패턴 · 템포 · 조성 · 노브값 · 음색 일부
       └─ 배정표(TONE_KIT) ── 프리셋이 안 정한 음색을 채움
                └─ 변주 풀 8종 ── 이 하위분기가 쓸 수 있는 변주 목록
```

### 3-1. 트랙 12개와 역할

| 트랙 | 분류 | 도메인 규칙 |
|---|---|---|
| `kick` | 드럼 | 칠 때마다 베이스·건반·리버브를 눌러 줌(사이드체인) |
| `snare` · `clap` | 드럼 | 백비트 담당. 장르에 따라 clap 이 탬버린·림샷이 됨 |
| `chat` · `ohat` | 드럼 | 오픈이 울릴 때 클로즈드가 초크 — 실물 하이햇과 같음 |
| `tom` | 드럼 | **음정이 있는** 막울림. 튠 노브를 따라감 |
| `perc` | 드럼 | **음정이 없는** 금속·나무. 튠을 안 따름 |
| `bass` | 음정 | 모노. 새 음이 이전 음을 끊음 |
| `keys` / `keys2` | 음정 | 화음. 스텝당 최대 8음 |
| `gtr` / `gtr2` | 음정 | 앰프 체인 경유 |

> **`tom` 과 `perc` 를 가른 이유**: Afrobeats 처럼 콩가와 셰이커가 **동시에**
> 필요한 장르가 있고, 둘은 튠 노브를 따를지 말지가 갈립니다.
> 따라간다면 `tom`, 아니면 `perc` 입니다.

> **`keys2` · `gtr2` 는 코러스 전용 레이어**입니다. 곡 구조를 켜면
> 코러스 외 6개 섹션에서 꺼집니다 — «후렴에서만 두꺼워지는» 편곡을 만드는 장치입니다.

## 6. 음색 배정 규칙

### 6-1. 우선순위 체인

```
① 프리셋이 직접 적은 kit   ← 있으면 무조건 이김
② 하위분기 배정표 TONE_KIT
③ 계열 폴백 TONE_KIT_CAT
④ 최종 기본값 {keys:'pad', gtr:'clean'}
```

베이스만 예외입니다: `kit.bass` > `TONE_KIT.bass` > `bcfg.eng`.
`bcfg.eng` 는 357개 전부가 갖고 있어 «기본값» 과 «일부러 정한 값» 을 구분할 수
없기 때문입니다.

### 6-2. 실효 범위 **[실측]**

357개 프리셋 기준으로 **배정표가 실제로 적용되는 비율**입니다.

| 필드 | 적용 | 비고 |
|---|---:|---|
| `keys2` · `gtr2` | **357 / 357** | 프리셋이 아무도 안 적음 |
| `perc` | 326 / 357 | |
| `gtr` | 251 / 357 | |
| `bass` | 197 / 357 | |
| `keys` | 153 / 357 | |
| **드럼 6트랙** | **0 / 357** | **프리셋이 전부 직접 적어 배정표가 못 이김** |

> **드럼 배정표는 지금 문서 역할만 합니다.** «이 하위분기에는 이 드럼이 맞다» 는
> 선언이자, 드럼을 안 적은 **새 프리셋**을 위한 기본값입니다.
> 기존 프리셋의 드럼을 바꾸려면 그 프리셋을 고쳐야 합니다.

## 7. 공통 설계 패턴 — 같은 구조가 8번

변주 규칙 8종이 **모두 같은 4단 구조**를 씁니다. 새 변주를 추가할 때 이 형태를
따르면 나머지가 저절로 맞습니다.

```
①  라이브러리      이름 → 규칙 정의        예: PROG, FILLS, GROOVE
②  하위분기 풀     하위분기 → 쓸 수 있는 이름 목록     예: PROG_KIT
③  계열 폴백       계열 → 목록                        예: PROG_KIT_CAT
④  해석 함수       프리셋명 → 최종 풀                 예: progPoolFor()
```

> 이 패턴 덕분에 **프리셋이 늘어도 규칙표는 안 늘어납니다.**
> 규칙은 하위분기(64)에 붙고, 프리셋(357)은 하위분기에 매달립니다.

## 8. 변주 규칙 8종

각 항목은 **루프 개수**를 주기로 돕니다. 전부 기본은 꺼짐이며, 끄면 지금 패턴이
그대로 반복됩니다.

| # | 변주 | 라이브러리 규모 | 무엇이 바뀌나 |
|---|---|---:|---|
| 1 | **Kit 셔플** | 엔진 186종 | 드럼 음색을 갈아끼움 |
| 2 | **패턴 셔플** | 프리셋 357 | 패턴을 다른 프리셋으로. 범위: 뱅크 순차 / 뱅크 무작위 / 장르 프리셋 |
| 3 | **필인 (FILLS)** | **18** | 루프 끝에 필인. 작은 것(S)과 큰 것(L)을 **따로** 돌림 |
| 4 | **선율 (MELODY)** | **98** | 건반 선율. 프레이즈 46개를 폼으로 조합해 생성 |
| 5 | **기타 리프 (RIFF)** | **27** | 기타 반복구 |
| 6 | **베이스라인 (BLINE)** | **31** | 베이스 라인 |
| 7 | **곡 구조 (SONG_FORM)** | **7** | 섹션 전환 (§10) |
| 8 | **화성 진행 (PROG)** | **30** | 마디마다 코드 전환 (§9). 컴핑 리듬 **20**종 별도 |
| — | **그루브 (GROOVE)** | **7** | 트랙별 타이밍·세기 편차 (§11) |

### 8-1. 선율은 «저장» 이 아니라 «조합» 입니다

`MELODY` 98종은 통째로 적어 둔 것이 아니라, **프레이즈 46개**를
`FORM`(AABA·ABAC 같은 결합 폼)으로 엮어 만듭니다. 16마디·32마디·64마디 길이가
같은 재료에서 나옵니다. 그래서 재료를 하나 늘리면 결과가 여러 개 늘어납니다.

## 9. 음악 이론 규칙

### 9-1. 스케일 (4종)

| 스케일 | 반음 배열 | 성격 |
|---|---|---|
| Minor Pentatonic | 0 3 5 7 10 12 15 17 | 5음. 힙합·록·블루스 기본 |
| Natural Minor | 0 2 3 5 7 8 10 12 | 7음 |
| Dorian | 0 2 3 5 7 9 10 12 | 7음. 펑크·재즈 |
| Major | 0 2 4 5 7 9 11 12 | 7음 |

### 9-2. 화음 생성 — `TRIAD(r)`

인덱스 `r, r+2, r+4` 를 켭니다. 7 을 넘으면 **7 을 빼서 자리바꿈**합니다.

> **⚠ 펜타토닉에서는 3화음이 아니라 «4도 쌓기» 가 됩니다.**
> 5음계에서 `r, r+2, r+4` 는 근음·4도·b7 이 됩니다.
> **이것은 버그가 아니라 의도입니다** — 힙합·록에서는 오히려 이쪽이 정확합니다.

### 9-3. 코드 진행 — `chordDegAt`

진행은 음도 배열(`degs`)이고, 마디 번호를 배열 길이로 나눈 나머지로 되풀이합니다.
예: `modal_i_iv` = `[0,3,0,3]` (모달 2코드).

### 9-4. 선택적 스냅 — `snapDeg`

선율 음을 그 마디 화음의 구성음으로 당깁니다. **다만 항상 당기지는 않습니다.**

```
이미 화음음이면        → 그대로
화음 밖이면            → 가장 가까운 구성음으로
그 거리가 너무 멀면    → 스냅을 포기하고 원래 음 유지
```

허용 거리는 7음계 2, **펜타토닉 3** 입니다. 펜타토닉은 8칸 그리드에 실음이
5개뿐이라 간격이 넓어, 같은 거리(2)를 쓰면 스냅이 걸릴 자리가 거의 없어져
규칙이 있으나 마나 해집니다.

> **업무 의도**: 화성을 맞추되 **선율을 망가뜨리면서까지 맞추지는 않습니다.**

### 9-5. 컴핑 — «무슨 음» 과 «언제 치는지» 의 분리

`chordSemis()` 는 **무슨 음**만 줍니다. 언제 치는지는 `COMP`(20종)가 정합니다.
둘을 나누지 않으면 컴핑이 아니라 롱톤이 됩니다.

`rows` 가 1개면 매 마디 같은 리듬, 2개면 마디를 번갈아 씁니다 —
몬투노처럼 엇박이 마디마다 미묘하게 바뀌는 스타일 때문입니다.

## 10. 곡 구조 규칙

### 10-1. 섹션 7종과 폼 7종

폼은 섹션 시퀀스입니다. 예: `popAABA` =
인트로4 → 벌스8 → 프리코러스4 → 코러스8 → 벌스8 → 프리코러스4 → 코러스8 → 아웃트로4.

### 10-2. 섹션이 하는 일 — 끄기 · 레벨 · 필인 · 뱅크

| 섹션 | 끄는 트랙 | 특징 |
|---|---|---|
| intro | 9개 (킥·베이스·햇만 남김) | 가장 얇음 |
| verse | 8개 | 베이스·기타 중심 |
| prechorus | 5개 | 쌓기 시작 |
| **chorus** | 2개 (톰·퍼커션만) | **가장 두꺼움.** 기타 ×1.55 · 건반 ×1.40 · `keys2`/`gtr2` 켜짐 · **뱅크 전환** |
| bridge | 6개 | |
| break | 10개 | 거의 전부 끔 |
| outro | 7개 | |

동시 발음 트랙 수: 인트로 3 · 벌스 4 · 프리코러스 7 · **코러스 10** · 브릿지 6 ·
브레이크 2 · 아웃트로 4.

> **⚠ 왜 레벨만으로 안 되는가 [실측]**: 배율만 바꿨더니 벌스↔코러스
> 라우드니스 차이가 2.33 LU 밖에 안 났습니다 — 마스터의 글루 컴프·리미터가
> 구간별 편차를 눌러 버립니다. 그래서 **트랙을 실제로 꺼야** 합니다.
> 압축기를 거쳐도 살아남는 건 «게인 배율» 이 아니라 «안 울리는 트랙 수» 입니다.

## 11. 그루브 규칙

7종. 각 그루브는 **트랙별로** 세 가지를 조정합니다.

| 항목 | 뜻 |
|---|---|
| `off` | 타이밍 밀기/당기기(초). 예: 레이드백은 스네어 +12 ms, 베이스 −4 ms |
| `swing` | 트랙별 스윙 세기 |
| `vel` | 트랙별 세기 배율 |

예: `laidback` = 스네어·하이햇을 살짝 뒤로, 베이스를 살짝 앞으로, 스네어 세기 ×1.06.

> **타이밍 오프셋은 BPM 을 안 따라갑니다** — «절대 밀림(ms)» 은 사람이 치는
> 습관이라 템포와 무관합니다. 스윙 배율만 박에 비례합니다.

## 12. 확률과 휴머나이즈

| 장치 | 범위 | 규칙 |
|---|---|---|
| **Chance** | 0~100 % | 스텝이 실제로 울릴 확률. 낮추면 성기게 연주 |
| **트랙별 확률(`prob`)** | 프리셋별 | 트랙마다 다른 확률. 357개 중 2개만 사용 |
| **Human** | 0~100 | 타이밍·세기·음정의 미세 흔들림. **0 이면 완전히 기계적** |

Human 이 0 이면 난수가 전부 1.0 이 되어 **재현 가능한 출력**이 됩니다 —
계측 하네스가 이 성질을 씁니다.

## 13. 충돌 회피 규칙 (예외 목록)

**«이건 왜 이렇게 돼 있나» 하고 고치려다 망가뜨리기 쉬운 자리들입니다.**

| # | 규칙 | 이유 |
|---|---|---|
| 1 | **베이스가 808이면 킥은 반드시 `tight`** | 둘 다 긴 서브면 저역이 충돌. 트랩 킥이 `808 Long` 이 아닌 이유 |
| 2 | 뜯는 위치 널(1/β)과 픽업 널(1/puBeta)을 **떨어뜨림** | 겹치면 그 배음이 두 번 깎여 구멍이 남 |
| 3 | 현 모델은 **서브 오실레이터를 안 씀** | 기음이 이미 최강 배음이라 덧붙이면 뭉갬 |
| 4 | 정규화를 먼저, 잡음을 나중에 | 순서를 뒤집으면 잡음 첨두가 피크를 먹어 현이 눌림 |
| 5 | 트루피크 실링 `oversample:'none'` | 4x 필터의 깁스 오버슈트가 첨두를 만듦 |
| 6 | 덕킹 실패는 **무시하고 소리는 냄** | 예전엔 덕킹 예외가 그 스텝 드럼을 통째로 무음으로 만듦 |
| 7 | 메탈은 건반 패턴을 **비움**(음소거 아님) | 음소거는 다음 프리셋까지 따라가지만 빈 패턴은 프리셋에 딸림 |

## 14. 데이터 거버넌스

### 14-1. 새 장르(프리셋) 추가 절차

1. `genres/` 에 근거 자료를 먼저 둡니다.
2. `src/data/presets/NN-계열.js` 에 프리셋을 씁니다.
3. `PRESET_SUB` · `PRESET_CAT` 에 분류를 등록합니다.
4. 하위분기가 새것이면 `TONE_KIT` 과 변주 8종의 `*_KIT` 에 풀을 답니다.
5. 청감 검증 전이면 `gen:true` 를 **반드시** 붙입니다.

### 14-2. 새 음색(엔진) 추가 절차

1. 파라미터의 **출처를 먼저 정합니다**(문헌·오픈소스·음향학 표준값).
   지어낸 수치는 넣지 않습니다.
2. 해당 파라미터표(`KENG`·`GTR`·`BSTR`·`BSYN`·`STRUCK`·드럼 표)에 추가합니다.
3. `ENGINES`(config.js)에 등록해야 UI 에 나옵니다.
4. **렌더해서 레벨을 재고** 기존 엔진 중앙값에 맞춥니다(10회 평균).
5. 출처와 환산식을 `docs/음색/` 에 남깁니다.

### 14-3. 라이선스 원칙

- 저장소로 **들여오는** 것은 MIT·Apache·OFL 만.
- **GPL 계열은 쓰지 않습니다** — 전염성이라 저장소 전체를 GPL 로 만듭니다.
- 상류에 **라이선스가 없으면 링크만** 겁니다(복사·재배포는 다른 행위).
