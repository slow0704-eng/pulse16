## 1. gtr/fuzz — 퍼즈  ❌ 5개 중 4개 불합격

A2(110Hz), 앰프·캐비닛 통과. `chord:[0,7]` 이라 5도가 배음 분석을 흐리므로
기음 판정은 **런타임에서만 `chord=[0]` 로 바꿔 단음으로** 다시 쟀습니다.

| 항목 | 실측 | 실물 기준 | 판정 |
|---|---|---|---|
| **기음 H1 (최강배음 대비)** | **−25.5 dB** (재현 −29.7 ~ −25.5) | 0 ~ −10 dB | ❌ **15~25 dB 부족** |
| 같은 값, 앰프 전(현 자체) | −4.7 dB | — | 현은 정상 |
| 홀수/짝수 배음비 | **0.0 dB** (앰프 전 +2.6) | +4 ~ +12 dB | ❌ 4~12 dB 부족 |
| 크레스트(압축감) | **17.2 dB** (clean 24.1 / hi 17.8) | 8 ~ 13 dB | ❌ 4.2 dB 초과 |
| 스펙트럼 중심 | **568 Hz** (재현 408~568) | 900 ~ 2000 Hz | ❌ 1.6~4.9× 어두움 |
| 600 Hz (clean 대비) | **+15.8 dB** (재현 +15.8 ~ +23.6) | −5 ~ −12 dB | ❌ **21~36 dB 반대** |
| 서스테인 기음 T60 | **3.38 s** (clean 2.44) | ≥ clean | ✅ |
| 1.0초 잔량 | **−5.4 dB** (clean −22.3) | — | ✅ 압축·서스테인은 잘 남 |

### 원인: `amp_fuzz` 의 드라이브 앞 하이패스 160 Hz ×2

`src/audio/graph.js` 의 `ampIn.amp_fuzz` 는 A2(110Hz)에서 이렇게 깎습니다.

```
highpass 160Hz Q0.7 ×2 → −14.9 dB   (110/160 = 0.6875)
highpass 110Hz (클리퍼 사이)        →  −3.1 dB
cab highpass 90Hz ×2                →  −1.3 dB
                                   합계 −19.3 dB
```

**이건 이미 한 번 고친 적 있는 버그입니다.** 같은 파일 `amp_hi` 에는
「150Hz 를 두 번 걸면 A2(110Hz)·E2(82Hz) 의 기음 자체가 사라진다.
기음이 최강 배음보다 24dB 낮게 측정됐다 → 100Hz 로 낮춘다」 라는 주석이
그대로 붙어 있는데, `amp_fuzz` 는 더 높은 160Hz 로 두 번 걸고 있습니다.

중역도 마찬가지입니다. `peaking 600Hz −7dB` 을 걸어 뒀지만
드라이브 게인 9.0 + 2단 하드클리핑이 만들어내는 중역 산물이 그것을
완전히 덮어써서, 실측은 **파임이 아니라 +15.8 dB 융기**입니다.

## 3. keys/vocoder — 보코더  ⚠ 절반 합격

**포먼트가 음정을 안 따라가는가 → ✅ 그렇습니다.**
같은 엔진에서 `KEYS_TEX.vocoder.body` 만 런타임에 떼어내고 다시 렌더해
나눈 값입니다(발음체·필터·ADSR 이 완전히 같으므로 차이가 곧 포먼트 응답).

| 설계 포먼트 | f0=110Hz | f0=164.8Hz | f0=220Hz | 설계 이득 |
|---|---|---|---|---|
| 620 Hz | 660Hz **+3.5** | 659Hz **+7.7** | 660Hz **+7.6** | +9 dB |
| 1100 Hz | 1100Hz **+5.6** | 1154Hz **+4.7** | 1100Hz **+8.7** | +7 dB |
| 2600 Hz | 2640Hz **+3.9** | 2637Hz **−4.5** | 2640Hz **+5.1** | +5 dB |
| 3400 Hz | (배음 없음) | 3461Hz **+2.0** | 3300Hz **+5.4** | +3 dB |

세 음정 모두 **같은 절대 주파수(660Hz · 1100Hz)** 에서 부스트가 잡힙니다.
음정을 따라가지 않는다는 요구는 충족합니다.
설계 F1 620 / F2 1100 / F3 2600 Hz 도 실물 기준(F1 500~800 · F2 1000~1500 ·
F3 2400~3000)에 전부 들어갑니다.

**그런데 포먼트가 "서지" 않습니다 → ❌**
실제 배음 포락선은 봉우리 없이 단조 감소합니다.

```
f0=220Hz  220Hz:0  660:−3  1100:−8  1540:−20  1980:−20  2420:−20 dB
f0=110Hz  110Hz:−4 330:0   550:−7   770:−11   990:−10   1210:−17 dB
```

원인은 산수입니다. 톱니의 자연 감소는 −6.02 dB/oct 이므로 f0=110Hz 에서
H1→H6(620Hz)만 해도 **−15.6 dB** 가 먼저 깎입니다. 포먼트 부스트가
+3.5~+7.7 dB 뿐이라 그 경사를 못 이깁니다. 실제 보코더/토크박스는
포먼트 사이 골이 15~25 dB 파여 봉우리가 뚜렷합니다.

또 `KENG.vocoder.f.hz = 3400` 의 24dB/oct 로우패스가 F3(2600)·F4(3400)를
코너에 걸치게 눌러, "모음" 을 만드는 F3 가 사실상 안 들립니다
(f0=220Hz 에서 2640Hz 배음이 기음 대비 −55 dB).

## 4. keys/harpsi — 하프시코드  ✅ 비조화도·감쇠 합격 / ❌ 밝기·벨로시티 불합격

C4(261.6Hz). 앱은 `KENG.harpsi` 가 아니라 `struck.js` 의 가산합성으로 냅니다.

### 비조화도 B — ✅ 합격

배음 n 의 **실제** 주파수를 옆 배음까지 거리의 45% 안에서 찾아 역산했습니다.

| 엔진 | B 실측 | B 설계 | H4 | H8 | H12 | 실물 기준 |
|---|---|---|---|---|---|---|
| harpsi | **1.17~1.29e-4** | 1.2e-4 | +1.0ct | +6.2ct | +14.6ct | 5e-5 ~ 2e-4 ✅ |
| (이론) | | | +1.7ct | +6.6ct | +14.8ct | |
| piano | **4.20~4.94e-4** | 4.2e-4 | +7.5ct | +25.2ct | +51.1ct | 3e-4 ~ 8e-4 ✅ |
| (이론) | | | +5.8ct | +23.0ct | +50.8ct | |

실측이 이론과 배음마다 **1 cent 안에서** 일치합니다.
harpsi 의 B 는 피아노의 **1/3.6 ~ 1/4.2** — 「피아노보다 낮은 비조화도」 ✅.

### 감쇠 — ✅ 합격 (기준 범위 안)

기음(261.6Hz) 성분만 추적해 회귀했습니다.

| 엔진 | 기음 T60 실측 | 설계 t60 | 실물 기준 | 판정 |
|---|---|---|---|---|
| harpsi | **0.92 ~ 1.86 s** | 1.3 s | 0.8 ~ 2.0 s | ✅ |
| piano | 5.83 ~ 6.60 s | 5.5 s | 4 ~ 7 s | ✅ |
| vibes | 4.00 s | 4.0 s | — | ✅ |
| marimba | 0.90 s | 0.9 s | — | ✅ |

vibes·marimba 가 설계값과 소수점까지 맞는 것이 **측정 방법이 옳다는 증거**입니다.
harpsi 가 0.92~1.86 으로 흔들리는 것은 unison 2줄(0, +2.2 cent)의 맥놀이
주기가 3.0초인데 음 자체가 1.57초에 끝나 창을 한 주기도 못 채우기 때문입니다.
**어느 값이든 기준 범위 안이라 판정은 바뀌지 않습니다.**

### 배음 기울기 — ❌ 불합격

비조화 악기는 `n·f0` 자리에 배음이 없으므로(harpsi H16 은 26cent = 63Hz 어긋남)
**찾아낸 실제 배음 주파수**의 진폭으로 쟀습니다.

| 엔진 | 기울기 실측 | 설계 tilt 환산 | H2 | H4 | H8 | H12 | 실물 기준 |
|---|---|---|---|---|---|---|---|
| harpsi | **−7.9 dB/oct** | −4.8 | −3 | −9 | −16 | −23 | −3 ~ −7 ❌ |
| piano | −7.6 dB/oct | −6.9 | −11 | −13 | −22 | −29 | −7 ~ −12 ✅ |

두 가지가 어긋납니다.

1. 기준(−3~−7)보다 **0.9 dB/oct 더 어둡습니다.**
2. **하프시코드가 피아노보다 밝지 않습니다.** 설계는 tilt 0.80 vs 1.15 로
   2.1 dB/oct 밝게 잡았는데, 실측은 오히려 0.3 dB/oct 더 어둡습니다.

원인은 `t60n` 입니다. harpsi 는 기본 감쇠가 1.3초로 짧은데 `t60n:0.40` 이라
H12 의 감쇠가 1.3/12^0.4 = **0.48초** 밖에 안 됩니다. 측정 창 중심(≈0.22초)에서
H12 는 27.5 dB, H1 은 10.2 dB 를 잃어 **차이 −4.8 dB/oct 가 기울기에 더해집니다.**
피아노는 같은 계산이 −2.0 dB/oct 뿐이라(감쇠가 5.5초로 길어서) 원래의
tilt 차이가 상쇄돼 버립니다. 즉 설계표만 보면 harpsi 가 밝지만,
실제로 울리는 동안에는 안 밝습니다.

### 벨로시티 응답 — ❌ 불합격

| 엔진 | 피크차 dB (vel 0.35 → 1.0) | 실물 기준 |
|---|---|---|
| harpsi | **5.2 ~ 6.2 dB** | < 3 dB ❌ |
| piano | 5.3 ~ 5.5 dB | 큰 편이 맞음 ✅ |
| clav | 0.5 ~ 4.0 dB | — |

`KENG.harpsi` 주석은 「건반이지만 현을 뜯는 악기라 벨로시티가 없습니다.
세게 눌러도 세게 안 납니다 — 그게 피아노와 갈리는 지점입니다」 라고 적혀
있는데, 실제로는 `struckVoice()` 가 피아노와 **똑같은** 곡선
`0.62*(0.30+0.70*vel)` 을 씁니다(0.35→1.0 이 5.3 dB). 의도와 구현이 다릅니다.

## 5. 앱 소스 수정 제안 (수치 포함)

> ⚠ 제약에 따라 `src/` 는 **읽기만** 했습니다. 아래는 제안입니다.

### ★★★ (1) `src/core/util.js` — `hold()` 가 서스테인을 못 잡습니다

**모든 현 악기(기타 17종 · 현 베이스 4종)의 지속음이 통째로 짧아집니다.**
`measure-tonal.html` 의 【2-B】 절이 이 버그를 3단계로 재현합니다.

```
① 현 코어(ksRender) 자체        설계 T60 5.50s → 실측 4.78s   (정상)
② 같은 버퍼를 guitarVoice 로 재생  실측 2.43s              (−12.1 dB/s 가 더 붙음)
③ hold() 만 떼어낸 재현 (ConstantSource 1.0 → GainNode)
      시각(초)   0.05   0.10   0.20   0.30   0.40   0.50
      현재 코드  0.820  0.640  0.390  0.238  0.145  0.088   ← 0.5초까지 1.0 이어야 함
      의도한 값  1.000  1.000  1.000  1.000  1.000  1.000
```

`cancelAndHoldAtTime()` 은 **취소할 이벤트가 뒤에 없으면 아무 이벤트도 남기지
않습니다.** 그래서 그 뒤의 `exponentialRampToValueAtTime(v*0.02, t+dur+rel)` 이
hold 지점이 아니라 **어택(t+0.0015)부터** 보간을 시작합니다.
음이 뜯기자마자 `dur+rel` 에 걸쳐 −34 dB 페이드아웃이 시작되는 셈입니다.

- **터지는 곳**: `hold()` 뒤에 곧바로 `*RampToValueAtTime` 이 오는 자리
  - `src/audio/voice-gtr.js` `guitarVoice()` (약 100행) · `guitarVoice2()` (약 143행)
  - `src/audio/voice-bass.js` `stringBass()` (약 48행)
- **안 터지는 곳**: `hold()` 뒤에 `setTargetAtTime` 이 오면 정상입니다
  (`adsr()` · `struckVoice()` · `windBass()` · `bassVoice()` 의 gsub/gh).
  실제로 struck 계열(piano·vibes·marimba)이 설계값과 정확히 일치한 이유입니다.
- **고치는 법**: `hold(p,t)` 자리에 유지할 값을 명시로 박으면 됩니다.
  `g.gain.setValueAtTime(v, t+dur)` 한 줄이면 위 ③ 의 "의도한 값" 이 나옵니다.
  (`hold()` 자체를 `hold(param,t,val)` 로 넓혀도 됩니다 — 다만 `duckSidechain()`
  처럼 유지값을 모르는 호출부가 있으니 기존 시그니처는 남겨 두세요.)
- **효과 추정**: 이것만 고쳐도 pedal 의 기음 T60 이 2.82 s → 약 6.8 s 가 됩니다
  (ksRender 버퍼 자체의 실측 감쇠). 실물 기준 5~10 s 안으로 들어옵니다.

### ★★★ (2) `src/audio/graph.js:103` — Tone.js 없을 때 `boot()` 이 죽습니다

```js
convolver.connect(revHP); link(revHP, widener);      // ← 여기
```
`link()` 는 `HAS_TONE` 이 false 면 `a.connect(b)` 로 가는데, 이때 `widener` 는
`nativeWidener()` 가 만든 **평범한 객체**라 `BiquadFilterNode.connect(object)` 가
`TypeError: Overload resolution failed` 를 던집니다. 바로 다음 줄
(`widener.output.connect(revReturn)`)은 이 경우를 처리해 두었는데 입력 쪽만
빠졌습니다. **"Tone.js를 불러오지 못했습니다" 폴백 경로가 실제로는 동작하지
않습니다** — `boot()` 이 리버브 배선에서 멈춰 채널 스트립·노이즈 버스가
아예 안 만들어집니다.
고치는 법: `nativeWidener()` 가 `{input, output, setWidth}` 대신 입력 GainNode
자체에 `output`·`setWidth` 를 붙여 돌려주거나, 103행을 `link(revHP, widener.input)`
로 바꾸면 됩니다. (하네스는 전자로 우회했습니다)

### ★★ (3) `src/audio/graph.js` `ampIn.amp_fuzz` — 기음 25 dB 실종

### ★ (7) `src/core/engines.js` `KENG.vocoder` — 포먼트가 안 섭니다

- `KEYS_TEX.vocoder.body` 의 이득이 톱니의 자연 경사(−6 dB/oct)를 못 이깁니다.

  **`f.hz: 3400 → 6000`** 으로 올려야 F3·F4 가 살아납니다.
